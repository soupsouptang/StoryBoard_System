# 下一代完整 UI 规划

日期：2026-10-05。状态：下一版本从零重构的设计储备，未实施；另行明确启动重构、完成需求及架构核查后才进入开发。当前版本不按本文修改。有效范围见[需求基线](REQUIREMENT_BASELINE.md)，参考取舍见[截图分析](REFERENCE_LAYOUT_STUDY.md)，字段排列、空间分配及窄屏降级见[布局细则](UI_LAYOUT_SPEC.md)。

实施顺序：先重构下一代架构及所需数据、命令、权限基础，完成对应验收，再开始本文UI布局的实现。现阶段仅继续完善文档；每个页面在对应基础就绪后领取独立写集，不能用参考布局推动本版本先行改界面。

## 1. 总体结构

全站层组织项目、我的工作、知识、账号及有权管理员入口。项目层按内容、人员与准备、计划与执行、审阅与交付组织，不按每张数据库表建菜单。一级入口控制在用户能稳定定位的工作组；按工种选择视图，不复制一套项目数据，也不由工种赋予权限。

项目入口从零设计，建议先比较“紧凑项目列表”和“可选封面的项目卡片”两种方案。封面不必整行铺满，无封面也有完整入口；名称为第一识别点，类型/画幅/帧率/镜头数/总片长为次级信息，最新活动和下一动作独立。个人任务摘要与项目导航分区，不铺满无实际数据的统计卡。默认呈现方式仍为提案，真实视觉验收后确定。

## 2. 页面共同排列

上方依次为全站位置、项目上下文、页标题与真实数量、模块切换、动作与查询工具；对象列表占主要面积。每个工作状态突出一个主动作，其余创建/导入、查询、排序、批量、列和导出为次级；危险动作不和新建同色。不要每行重复完整标签，使用稳定表头和对齐列，必要的行内标签保留。筛选条件就近展示，可一项项移除；空结果仍保留筛选和清除入口。

桌面壳层建议顶栏48—56px，展开导航200—232px；正文边距20—28px，区块间距16—24px。它们是新设计起点，不是旧 CSS 的复刻。shadcn/Radix 控件保持体系一致，字号、边界、浮层和交互从新主题定义；白天/夜间语义一致。

## 3. 信息密度

| 表现 | 建议尺度 | 必须同屏的信息 |
| --- | --- | --- |
| 单行数据列表 | 鼠标密集视图40px起；正文14—16px | 身份、关键字段、状态与可达动作 |
| 双行场景条 | 52—64px；标题与摘要均14px起 | 编号、环境/标题、短描述、日期/组、需求和待确认 |
| 任务行 | 48—64px，固定输入需第二行时自然加高 | 标题、主责、输入、阶段、计划、下一动作 |
| 人员卡片 | 约264—336px宽、128—160px高 | 人员/角色区分、名称、关联及当前安排摘要 |
| 触屏列表 | 行高56px起，独立点击区至少44px | 不依赖悬停，不把桌面微小图标直接缩小 |

1440×900、100%缩放时，普通场景列表目标约10—12条双行信息；1920×1080约14—16条。按实际可用高度扣除壳层、工具及翻页区后计算，详情、长中文、200%文字缩放和触屏可自然加高；不能为达标把字压到无法阅读。所有尺寸为提案，使用相对单位适应文字设置。身份、标题、当前工作状态始终优先，其余按任务视图选列；细节进入展开或对象页。表内横向滚动，身份列固定，整个页面不溢出。个人屏幕适配不回写共享行高、列宽或列显示。

视觉分三层：身份和下一动作、影响当前工作的字段、深层来源与历史。彩色用于小语义标识、用户协作色和必要冲突，不能将整行绿/黄/紫直接当完成状态。选择、工作阶段、环境和保存状态分别表达。标题截断有完整查看方式，中文说明不挤坏右侧固定字段。

## 4. 场景与剧本

场景采用密集列表/条带主视图。左侧窄编号，第二区环境与标题加一行摘要，右侧按列对齐拍摄日、摄制组、剧情角色、镜头数、预计拍摄时长、剧本页占比和缺项。顺序不等于拍摄顺序；同一场景跨日安排回查条目，不能复制创作身份。

工具栏左侧新建和导入，右侧搜索、筛选、排序、多选、统计、列与导出。批量模式选中后出现动作条，说明是否包含未加载结果。空状态只给一段解释和“新建场景/导入剧本”，无示例数据冒充真实内容；识别结果要预览。

剧本为独立内容视图，按场景与明确角色映射；宽屏正文和批注并排，中等屏收起批注，手机阅读与批注分别切换。批注固定版本与稳定段落锚点，版本差异保留来源。可回复和有权提及，发布批注不自动分发剧本；讨论、解决问题和正式审阅是不同动作。

## 5. 分镜工作台

重新设计表格、卡片、视觉墙、时间线四种同源视图，不复制镜头记录。默认九列；预设与自定义在列管理选择。表头和身份列固定、列宽/行高支持手动与自动；共享视图的同步配置不受个人窗口测量污染。读优先，明确点击编辑；结构修改与普通字段编辑分别校验。

镜头详情在专用编辑区呈现正文、有效场景、摄影/灯光计划、图片/面板、旁白与关联任务，表格和详情使用同一命令合同。布局由下一代重新设计，不受旧卡片、弹窗、胶囊控件或工具栏几何约束。无可见审阅标记不显示空评论列，但可从审阅入口回查。

列管理分可用、当前和已删除；内置只可删除恢复，预设/自定义才可确认永久删除。选列、调宽和筛选不是删除。右键按行、列、单元格、空白、图片和选择提供实际动作，并有键盘及触屏替代。

## 6. 演职人员

现实人员、剧情角色、出演关系、岗位任职、档期分别保存。页面可以页签组织这些对象，卡片与列表切换只改变展示。默认人员卡片左侧身份/岗位/当前工作，右侧固定比例头像；角色卡片显示角色名和选角关联，不把头像人物当角色定义。无演员、未使用和待确定分别显示，不能统一叫未使用。

图文卡片桌面按容器三至四列，中屏两列、手机一列或列表；头像等比适配，无头像不塞装饰图。私人电话不进默认卡片。搜索后显示真实有权数量，兼任只算一名人员；多人同岗按身份分行。

工作日表按人/角色关联显示日期网格，计划、实际、可用、暂定、未知及不可用分轴。文字图例优先；没有资料的日期不画连续工作线。开始/结束工作标记只从指定方案明确条目派生，不推断薪酬、待命或连续可用。

## 7. 任务与后期

列表、部门看板和依赖时间线查询同一任务。主责头像/姓名、协作数量、当前阶段、固定输入、缺项和下一动作同屏。来源变更显示失效原因；自动停用边界按业务合同，历史不删除。

依赖图允许多输入汇合，时间线区分计划、基线、预测和实际；已开始与锁定项不自动移动。剪辑初版和特效预演可并行仅因依赖允许，不因参考图画在同一天就开放；导演意见/审阅节点须有固定受审版本与负责人，评论数量不作为通过。连线可键盘编辑，拒绝循环。

## 8. 排期

方案、摄制组、日期范围和当前标识置顶。默认只读浏览，显式进入编辑并显示租约/保存状态；不是全页遮罩锁，也不是任何人点编辑就取得权限。方案比较保留真实来源，设为当前为独立有权动作。

新排期页面提供“场景条带”和“时间线”切换。条带按阶段/拍摄日分组，紧邻组标题显示日期/组与冲突数；每行时间、场景、标题摘要、环境、地点、关联镜头、人物要求。日末汇总显示拍摄、准备、转场、休息和未知，预算工时与安排跨度分开。各类条目真实参与安排，日末汇总仅派生不建立空业务对象。

时间线支持待安排队列、中央时间安排与选中检查；空间不足时一次展开一个辅助区，不长期三栏压缩主视图。转场按撤收/装载/行驶/卸载/搭建计算，避免与相邻条目双计。超时只改未来预测，不取消未拍镜头。独立未排期需求另列。

## 9. 通告、现场与时间段需求

通告工作页采用编辑目录、白纸预览和来源/接收检查；将模板顺序与业务修改区分。纸张首部三列，公司/必要联系人、拍摄日及大号集合时间、可选环境/医疗信息；后接部门集合紧凑表、地点/地图、当日安排、人员和准备。个人手机页突出本人集合、日期/时区、修订和差异，再到地点、准备、安排和确认。

现场页重点是现在、接下来、已发生与预计收工；实际开始/结束/更正和未完成镜头回查，不变成全项目管理大屏。时段需求按时间、型号/道具、数量、来源与共用组展示；只能说明需要什么，不能暗示库存可用。

## 10. 素材、画板与旁白

素材列表/网格同源，上传、命名、分类、搜索、引用、默认构图、版本、下载及删除恢复完整可达。默认构图修改只影响未专用覆盖的当前引用；内容版本固定有效构图。裁剪预览横竖、21:9、16:9和自定义，原比例不拉伸，适配黑填充；縮略图生成不阻塞正文编辑。

灯光二维/分屏/三维共用画板对象；选中后才展示属性，个人视角不写成创作更改。情绪板支持图片、便签、色卡、链接、框选和撤销，不进入创作版本。导入、渲染和三维用成熟库，独立模块负责，不在 UI 写业务解析器。

旁白与镜头关联，预计朗读时长、实测音频、语速与声音语言分开。滑杆借鉴 Codex 档位交互：当前倍率/文字和可播放 TTS 样例，拖动即时显示，生成异步可取消；样例不是正文配音完成事实。

## 11. 审阅、交付与知识

创作版本显示提交作者、时间、说明、全项目差异和镜头级入口。左右比较折叠未改部分，增删有文字/图标，图片同比例。批注与审阅决定独立历史；返工和补拍要求回查问题、固定版本、主责和安排。

交付区分生成文件、正式提交、送达、验收和退回。退回关联返工，旧验收不覆盖；授权链接显示字段、范围、期限、撤销和下载/评论权限。知识页为型号/基础知识、岗位目录、经验、统计和候选建议；候选核验和接受对项目的影响两步处理。

## 12. 动画、异步和多端

动效提案：选择/按钮100—140ms，菜单140—180ms，展开/侧区160—220ms，重排邻项120—180ms，影响提示200—260ms；拖拽本身即时，不加缓动输入延迟。可打断，不加产品 Reduced Motion 开关，不用全屏庆祝/持续脉冲打断编辑。

保存有草稿、提交中、服务器已保存、失败、冲突；更新时刻来自服务端。协作先拿编辑租约，用户色指针与字段高亮附名字；重连校验权限及修订，草稿不被刷新吞掉。错误说明没完成的步骤和保留的输入，能重试的定位到失败目标。

桌面优先结构化编辑；平板调整为主区+单辅助区；手机以本人通告、当前任务、现场登记和审批/审阅阅读为重点。复杂操作分步骤，不用缩小截图替代。横屏、竖屏与软键盘保留上下文；个人卡片/展开不改共享视图。发布与确认必须收到服务端回执，不离线假成功。

## 13. 进入实现后的验收

每个模块验证空、加载、无权限、失败、冲突、多选、长内容、多人编辑、删除恢复、永久删除和迟到结果。真实桌面与触屏检查可读性、可点性、焦点、滚动和密度；纸张/个人页分别验证，参照图不当运行证据。全新空库和合成项目走通 AGENTS 的主制作链。当前全部为未实施，不沿用旧验收结果。
