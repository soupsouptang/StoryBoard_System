## 1. 当前授权范围

明确启动下一代工作后，先重构并验收对应架构、数据、命令和权限基础，再开始该UI页面实施。当前详细布局仍为待用文档，不授权先改本版本界面。

下一代不使用当前项目任何实现资产：旧代码、UI、组件、模板、样式、图片、模型、用户工程、数据库内容、媒体、凭据、运行配置和测试输出均不复制、不迁入。项目入口重新设计，取消整行照片封面必须保留的限制。参考旧需求是理解产品行为，不是取得复用旧实现的许可。第三方成熟库可重新选型，不能手写已有稳定轮子。

不纳入新版不等于删除旧环境。本轮已授权删除本规划分支的Git跟踪旧实现副本；禁止破坏master运行应用、真实业务数据、素材、截图、备份、部署和他人草稿。规划图仅使用合成文字和图形，原附件不直接推送。不得将参考图中的个人资料或外部 Logo 作为新版种子数据。

## 2. 技术和数据设计

沿已确认技术方向评估全新应用：Node.js 24、Next.js/React、shadcn/Radix、FastAPI、异步 SQLAlchemy、PostgreSQL、Alembic、Redis 临时协作与独立媒体存储。精确版本在实现启动时核查官方发布和兼容矩阵、锁定依赖；不要写未经验证的“最新版本”。旧目录名、包路径和依赖锁不是新架构硬约束。当前只规划，不创建第二套运行应用。

每个能力一个权威负责人。页面、接口、命令、权限、历史、事件、数据模型、媒体和渲染分别写清职责；不要把导入、排期、交接和导出挤成一个大模块。新增一级对象的准入需写使用者、独立生命周期、作用域、归属、关系、删除及验收。父子表达真实所有权和生命周期；独立对象的联系使用明确类型的连接，不因 UI 排列或业务关联建立层级。

全新数据库从空库迁移到 Alembic head；不做旧数据库回填、双写、旧 API/DOM 兼容。项目、任务、排期和知识的字段标准按需求基线设计；不全塞 JSON，不设可运行任意脚本的规则或插件系统。原图不可变、版本固定、缩略图异步生成。时间为 UTC 事实加明确项目时区；时码通过分数帧率计算，片长、拍摄工时与实际时间分开。

## 3. 必须守住的业务合同

权限独立于工种；列表、计数、历史、媒体、实时结果、导出、链接和缓存统一校验项目及字段权限。普通项目授权保留明确拒绝规则；与已确认Team/Agency管理员范围冲突的优先级按[权限合同ACL-02](requirements/PERMISSION_RULES_2026-10-05.md#8-细粒度权限待确认)等待确认，不自行实现绕过或剥夺管理权。授权变更使连接和缓存重新校验。账号、现实人员、剧情角色分开，同名不合并。

命令包含身份、预期修订和幂等键。持久数据、回执、审计、可撤销历史及待发布事件在同一事务完成；提交后才返回已保存。无变化不制造内容版本或更新时间。冲突保留草稿，不用最后写入覆盖别人。异步作业可取消、可定向重试；迟到结果检查来源修订、权限和永久删除标记。

项目创作提交包括场景、镜头、有效构图和灯光等内容；镜头提供左右比较入口。人员隐私、权限、任务执行、交接、通告发布、批注及审阅各自历史；共享视图和情绪板不进入创作提交，情绪板仍支持撤销。真实发布和实际执行使用更正、撤回或新修订，不能普通撤销抹掉事实。

默认九内置列；预设按需添加，自定义列有稳定定义。内置可删除恢复但不可永久删除，预设和自定义永久删除先预览确认，再清当前值及受控历史正文。内部身份和权限字段不显示且保留。普通列/制作对象只有删除、永久删除，不增加通用归档动作；组织解散后项目保留归档按[组织合同](requirements/USER_TEAM_AGENCY_RULES_2026-10-05.md)的特定规则处理。共享视图同步列显示/顺序/宽度、行高、筛选/排序/分组，个人选择、光标、草稿和视角独立；不支持自定义列高。

场景与镜头多对多，主场景可不设、最多一个；镜头动态继承关联场景要求，逐项增补、排除、替换、恢复继承。镜头显式环境优先，否则主场景值附差异；缺值不猜。需求不是实际演员、准备已完成或资源可用。

任务一名主责、多名协作，固定输入输出。自动失效仅停用未开始、无实际、无产物、无交接的系统任务；其他事实保留。必需检查和项目配置的授权资料决定可开始，未知不通过。检查只判断具备/遗漏，不建立操作教程。正式素材交接检查完整性及项目配置的备份；预览不能满足正式输入、审阅或交付。

排期方案、已发布通告、个人反馈和实际事实分开。排期变化只更新通告草稿和差异；有权者明确发布、明确发送，不能自动对外发送。查看、确认、到场分开；旧确认绑定旧修订。评论解决不等于审阅批准；交付渲染不等于正式交付，退回形成返工/补拍关联。

只做时段灯光器材和道具需求、型号及基础知识；独立需求相加、明确共用一次，不做库房、库存、预留、采购、费用、复杂耗材和使用教程。经验原文项目隔离，新贡献固定采集时成员全部团队，换组只影响新经验；合格汇总至少10个独立执行单位、3个项目。每天最多3个非阻断主题。AI 候选附独立证据并人工验证后入库，不直接写业务数据库；未配置或授权时不外发 AI 请求。

## 4. UI 和导出

从零设计，借鉴截图的信息密度与排列；shadcn 是组件和交互基础，不是排期业务引擎。所有尺寸和导航为提案，不能搬用旧 CSS 或把小字满屏当专业。动作文本清楚，桌面与手机同一事实来源；局部横向滚动不造成整个页面溢出。设计有意义、可打断的动画，不增加产品 Reduced Motion 开关。

右键随对象、选择、权限变化，并提供更多按钮/触屏入口。复制剪切粘贴保留原生文本和输入法；行向下粘贴、列向后粘贴；不增加独立 duplicate 动作。永久删除需确认、不可撤销。

导出允许字段模板、横竖纸张和图框各自配置；图片不拉伸，适配后黑填充。纸张、个人通告页读取同一固定发布修订。工程 QR/DM 分片与隐写水印分别真实解码验收。所有输出不写免责声明；能力限制写在测试报告，不能假称抗所有截图或裁剪。

## 5. 多 agent 协作与验收

实施启动后，每包登记允许写集、排除写集、基础提交、依赖、接口、负责人和验收证据。公共组件、共享协议、路由入口、数据库迁移链及锁文件由集成负责人串行整合；模块 agent 不覆盖别人的未提交修改。新增依赖核查许可证、锁文件和真实消费者。当前不沿用旧清单进度，全部从未实施开始登记。

仅应用合成或获准脱敏的新版样例。应用测试要覆盖空库迁移、事务、并发、幂等、授权、删除、迟到结果、导出回读；UI 需真实浏览器正常缩放及多端截图。看板数值下钻同一口径，未知不作零。示意图、空 API、单个模型或构建通过都不等于完成。

闭环验收：项目 → 场景/镜头 → 任务 → 人员/需求 → 排期/转场 → 通告 → 实际 → 固定素材交接 → 后期产物 → 版本/审阅 → 返工或补拍 → 交付 → 合格经验校准。每步有固定来源、负责人、权限、失败结果和回查入口。

不明确的所有权、授权角色、默认岗位、跨团队共享、数据删除或状态跃迁先问用户。已确认规则不重复询问；设计参数明确写成提案。结束时更新本目录事实记录，列真实检查和未实现部分，仅显式暂存本包文件再推送本分支。
