# 下一代 UI：信息密度、布局与排列细则

日期：2026-10-05。状态：设计储备，未实施。只用于 `docs/next-generation-plan` 的 `next-generation/`；明确启动下一代重构并核查需求、架构和写集后才开发。当前版本 UI 与本版本执行文档不使用这些布局提案。

顺序要求：先完成相关新架构、数据、命令和权限基础的重构与验收，再实施对应UI页面。本次继续写规格，重构和UI开发均未启动。

上位合同：[已确认需求](CONFIRMED_REQUIREMENTS.md)、[全模块 UI 规划](UI_PLAN.md)、[导出设计](EXPORT_DESIGN.md)。截图依据及取舍见[参考分析](REFERENCE_LAYOUT_STUDY.md)。下述尺寸、默认排列和交互为设计提案，后续按真实内容验证；不继承旧实现、数据、素材、封面要求或旧功能黄金基线。

## 1. 把参考中的密度转成可操作规则

使用者先辨认对象，再横向比较时间、关联和缺项，最后执行动作。密度来自固定表头、稳定列、同类字段对齐与逐层展开。长名称和关键差异需要完整读取，不以固定条数裁掉正文。

| 信息层 | 默认可见 | 展开后可见 | 排列方式 |
| --- | --- | --- | --- |
| 身份 | 场景/镜头编号、姓名或任务名 | 稳定身份和来源版本 | 靠左，编号窄列，名称占主要弹性宽度 |
| 当前工作 | 时间、地点/组、主责、状态、缺项 | 多个安排、完整关系、冲突对象 | 中右侧固定比较列；缺项用文字及标识 |
| 深层来源 | 有影响时显示来源/差异入口 | 历史、权限内明细、固定输入输出 | 详情区或专用页，不把每个字段铺进主列表 |

行身份、正文链接、选择框、更多按钮分别承担自己的动作。点击正文进入详情，点击选择框只改变选择；行内操作不同时打开详情。卡片不嵌套按钮或链接。状态、选择、焦点、协作人、保存反馈各有独立表现。

新主题保持同一字号、间距、边界和状态令牌。普通界面正文14—16px，手机正文16px起；编号/时间/数量采用等宽数字，文本靠左、数量靠右。未知、未填、不适用及真实零有明确文字或图例。环境类别以小标签表示；整行背景只适度表达选择或关注，不把内外景/昼夜配色混成完成状态。

## 2. 页面骨架、空间和滚动

| 层次 | 内容 | 空间提案与行为 |
| --- | --- | --- |
| 全站 | 项目切换、我的工作、账号 | 顶栏56px起，不能遮挡焦点 |
| 位置 | 项目及当前工作组 | 单行24px起；长路径折叠中间项，保留当前标题 |
| 页面 | 标题、有权数量、必要方案/修订 | 标题行40px起；不用多个大数字卡片挤压对象 |
| 对象切换 | 场景/剧本、人员/角色、条带/时间线等 | 一行36—44px；窄屏可折到有标签的选择控件 |
| 当前任务工具 | 主动作、搜索、筛选、排序、列、导出 | 40—44px起；多选时就地切换为选择动作条 |
| 对象 | 表头、行/卡片、分组及就近汇总 | 列表占主体；详情只在需要时展开 |
| 范围 | 已显示/筛选结果、上一页/下一页 | 32—44px起，读得到当前范围；不默认无限滚动 |

单位为16px根字号下的示意等价值，实施时转为相对单位。以顶部各层及间距约280px、翻页区32px计算，900px高窗口约余588px；52px双行可见约11条。1080px高窗口约余768px，可见约14条。该计算说明空间取舍，窗口较窄、标题换行、展开详情或文字放大时条数减少是正常结果。

桌面导航展开宽约216px、正文左右边距各24px。1440px窗口可用正文约1176px；1024px窗口先收起导航、减少并排区，不靠缩字号塞下全部内容。卡片列数按容器实际宽度计算，不能只按设备名称决定。

列表采用一个主要垂直滚动区，工具栏/表头在该区正确吸附；表头和行共享横向位置。横向滚动限于表格或时间轴，页面标题、导航及主要动作不随之消失。详情区如需独立滚动应有明确标题和边界，避免滚轮穿透带动背景。手机以页面纵向阅读为主，局部网格保留可发现的横向滚动入口。

宽屏并排详情建议320—384px；主区不足以保留身份、标题和关键时间时改为抽屉或对象页。非模态详情不困住键盘焦点；模态抽屉/确认框管理焦点与返回。关闭详情回到原对象、选择和滚动位置，底部吸附操作不遮住最后一条记录。

## 3. 密集阅读、触屏与文字放大

| 环境 | 列表起点 | 工具和细节 |
| --- | --- | --- |
| 鼠标密集阅读 | 单行40px；双行52px；正文至少14px | 工具32—40px视觉高度，常用动作可见，更多有标签 |
| 默认阅读 | 单行48px；双行56—64px | 保留标题与摘要；长内容按实际行数增高 |
| 触屏 | 行56px起；独立目标至少44px | 更多常显，拖拽有按钮替代，禁止悬停才可操作 |
| 200%文字或缩放 | 自然换行、自然增高 | 主区转单栏，保持关键值和完整查看入口 |

共享视图保存用户明确设置的行高、列宽、顺序、筛选、排序和分组；设备临时适配仅改变个人渲染。例如手机将共享表投影成信息行、增加点击面积，不把这个变化同步成他人的列配置。显式修改共享视图仍显示其影响范围，手机不能悄悄为所有人隐藏列。

标题最多两行摘要只是初始布局，全文可从详情/展开读取。关键时间、场景号、冲突原因和当前修订不能只藏在悬停提示内。文字扩大后不保持固定高度截断内容；没有头像或图片也维持完整识别。

## 4. 场景条带：先识别，再比较

### 4.1 桌面默认列顺序

以下是场景阅读视图，不是更改分镜默认九列。场景列表按创作对象一行；拍摄日、摄制组等为指定方案的有权派生信息，多次安排用摘要和展开表达。

| 顺序 | 字段 | 宽度起点 | 优先级和溢出方式 |
| --- | --- | --- | --- |
| 1 | 选择 | 44px | 常显；表头明确选择范围 |
| 2 | 场景显示号 | 64px | 身份；支持2A等编号，不按数字强转 |
| 3 | 环境/场景名及摘要 | 最小280px，分配剩余宽度 | 第一行标题，第二行短描述；全文可达 |
| 4 | 拍摄日 | 112px | 默认当前指定方案；多个日期显示“2个拍摄日”等入口 |
| 5 | 摄制组 | 96px | 同一方案多组不填成一个任意组 |
| 6 | 关联镜头 | 64px | 当前有权去重数量，可下钻同范围 |
| 7 | 预计拍摄 | 112px | 如“45分钟”，未知写未知；不显示成片时长 |
| 8 | 准备/缺项 | 120px | 文本摘要，如“缺2项”，可查看来源 |
| 9 | 更多 | 44px | 常显，名称带对象身份 |

上述固定宽度合计756px，含标题最小宽度后总宽约1036px；1176px正文下标题区可分到约420px。角色、剧本页占比、剧情日、具体需求为可选比较列，列管理可加入，空间不足则局部滚动。选列和宽度是提案，不把角色、地点或日期缺失补成示例值。

### 4.2 行内信息与移动排列

桌面第一行是“编号｜内外景·地点/场景名·昼夜｜日期/组｜数量/时长｜缺项”，第二行只放内容摘要或有影响的差异。原始剧本次序、显示排序和拍摄顺序分别标明；排序不直接重编号，筛选后的拖动不重写隐藏对象次序。

手机变为编号与标题、摘要、日期/组与缺项三层；时间和下一动作优先。关联数量与额外专业字段放在可展开的“安排与需求”，选中模式保留选择入口与对象数量。一个场景两天拍摄仍是一个场景，展开后显示两条具体安排。

工具左侧突出新建场景，导入剧本为次级；右侧搜索和筛选，排序/列/导出次级。已有数据时不要重复大幅功能介绍；首次空状态给新建和导入两个有权入口。筛选为空显示当前条件与清除，读取失败保留筛选和重试，无权限不暴露总量。

## 5. 人员与角色卡片：固定骨架，完整关系

卡片首选左侧文字、右侧头像，宽约280—336px、高约144px起，12—16px间距。文字分名称、身份/任职或出演关系、关联场景/任务、当前安排与待确认四层；头像区约80—96px宽，保持原比例，不强制拉伸或复用参考照片。更多按钮占自己的区域，不压在姓名上。

人员卡显示现实人员名和有权任职，角色卡显示剧情角色名及明确出演关系。角色未选演员显示“未选演员”；未关联场景显示“未关联场景”；档期没有资料显示“档期待确认”。这些可同时存在，不由同一个“未使用”标记替代。兼任只算一名人员，姓名相同不合并。

正文宽1176px且卡片最小280px、间距16px时可排四列；正文约940px为三列；约768px为两列；手机一列或紧凑列表。只有一两条资料时自然左对齐，不放大卡片或补装饰卡填满。长岗位多行或“另有2项”展开，不能让头像挤掉姓名。

列表切换用于比较部门、任职、档期和任务，读取同一事实；切换保留筛选、排序、选择及有权范围。私人电话默认不展示，详情和导出重新校验字段权限。卡片里显示头像不创建演员/角色关系，点击岗位不自动授权。

## 6. 排期条带与拍摄日分组

顶部明确方案、当前标识、摄制组、日期范围、项目时区与浏览/编辑状态。主动作随状态变化：浏览态为有权进入编辑；编辑态突出当前保存/冲突处理。设为当前、比较、生成通告草稿分别为明确动作，不靠参考中的黑色横条表达全页锁定。

| 区域 | 固定排列 | 规则 |
| --- | --- | --- |
| 拍摄日标题 | 日期/拍摄日号 → 摄制组 → 冲突/未知 → 更多 | 就近位于本日条带前；按方案日期及组组织 |
| 安排行 | 起止 → 类型/场景号 → 标题/地点 → 人员/镜头 → 时长/缺项 → 更多 | 身份与关键时间优先，正文弹性宽度；可增高 |
| 非拍摄条目 | 类型 → 起止 → 真实说明/来源 | 准备、转场、休息各有文本类型，不套假场景号 |
| 日末汇总 | 本日标识 → 拍摄/准备/转场/休息 → 安排跨度 → 未知 | 与本组结束紧邻，弱分隔，不能单独悬空在下一页 |
| 未排队列 | 对象身份 → 未安排原因 → 时间/需求缺项 | 保留未安排事实，筛选不让它们消失为已安排 |

日末汇总不是“已完成”；安排跨度是最早开始至最晚结束，工时按口径计算，不能简单相加并行组时长。过滤日期/类型后明确“筛选结果汇总”与“全日汇总”的范围；后者只能包含仍有权的条目。预计未知单列，不能因有0分钟示例把未知算零。

创作场景可关联多条安排，安排项有自己的身份和修订。跨日、补拍、分组显示时仍回查同一场景/镜头；场景号重复不合并。跨午夜标完整当地日期或“次日”，两个摄制组同时间分列/分组，不串成一个假单线日程。

条带用于横向比较，时间线用于时间关系；切换保留方案、日期、组、选择及滚动锚点。时间线按刻度横向滚动，对象名和当前日期可定位；拖动先显示落点时间、受影响条目和冲突，释放后由服务端确认。提供“移动到拍摄日/调整时间”的键盘和触屏路径。来源冲突保留本地草稿，明确已开始/锁定项不可自动移动。

转场详情按撤收、装载、行驶、卸载、搭建排列，缺一段就提示未知；与相邻准备时间去重。超时区分旧计划与新预测，突出下一项预计开始和预计收工差异，不把迟到预测画成已发生，不自动取消镜头。

## 7. 工作日表、剧本和后期时间线

| 页面 | 主区 | 辅助区 | 窄屏表达 |
| --- | --- | --- | --- |
| 演职人员工作日表 | 左固定姓名/角色，顶部日期，格内计划标记 | 指定方案、摄制组、文字图例及统计口径 | 保留身份列、局部滚动日期；单人可切日期列表 |
| 剧本 | 场景标题 → 动作 → 角色 → 对白，正文约60—75字符阅读宽 | 场景目录及版本固定批注 | 正文/批注分别进入；返回同场景和段落 |
| 后期依赖 | 左侧任务/主责，右侧时间条与连线 | 固定输入输出、缺项及依赖详情 | 任务列表优先，单项展开前置/后继 |

工作日表的工作、首次/最后工作标记从指定方案派生。档期可用、暂定、不可用、未知独立显示，不因当天有工作就改写本人档期；空白线段不代表工作、待命或连续可用。身份与日期交叉格可打开当天明细，虚拟化时仍可键盘定位日期。实际记录使用独立文本/轨道，与计划分开。

剧本批注区建议320px起，空间不足改为抽屉/独立页。批注固定场景、内容版本和稳定段落，阅读顺序不因浮动卡片乱序；回复在原线程内展开，提及只列有权目标。正文修订后旧批注显示锚点状态和旧版本入口，不能挂到同名新段落。正式剧本打印不自动印评论。

后期时间条以任务名称、主责和状态为核心，颜色仅辅助区分轨道。多输入汇合可以表达等待关系，但固定版本及正式接收决定可开始；“导演意见”必须指向受审版本与责任人。计划/基线/预测/实际分别可辨；没有预计时长显示待补充，不造等长任务条。连线能从依赖表编辑，拒绝循环并定位原因。

## 8. 通告工作页与个人手机页

桌面工作页把模块目录、白纸预览和来源检查组织为可收放区。中等宽度只显示预览加一个辅助区；纸张预览可以缩放，编辑控件维持正常字号。来源检查列出缺项、过期输入、接收范围和未确认变化，不能把模板列宽修改当业务事实修改。

流程突出一个当前动作：生成草稿 → 检查/预览 → 发布指定修订 → 明确发送。发布与发送分别返回结果；“已发布，发送2项失败”提供定向重试，不回滚发布也不重发成功项。接收人数和“待确认”从指定修订及授权范围读取，不把旧修订确认算作新修订确认。

个人页首屏按下列顺序排列，重要差异可自然扩展高度：

1. 项目、拍摄日期、摄制组、时区与修订；旧修订/撤回/到期提示在前。
2. “本人集合”及32—40px起的大号时间；总体集合另有标签，缺本人时间显示待确认。
3. 本次重要变化：旧值 → 新值，例如集合时间或集合地点变化。
4. 集合地点、完整可读地址和本人准备；导航入口仅在授权地点及服务可用时显示。
5. “确认已阅读修订 N”，再到本人的当日安排与有权完整文件。

手机不能将一整张纸缩成主阅读页。320/375/390px宽下时间不截断、长地址多行、操作至少44px；底部操作若吸附则预留安全区和内容空间。打开只表示查看；确认等待服务端回执，失败显示未确认并保留重试入口。登记到场是另一动作，不能和阅读确认合并。

纸张页头三分区、部门集合、地点、当日表、人员准备及日末汇总的精确顺序/尺寸见[导出设计](EXPORT_DESIGN.md)。纸张与个人页读取同一固定发布修订，各自按权限投影，不因不同排列产生第二份通告事实。

## 9. 选择、查询与对象动作

| 交互 | 默认表达 | 失败/变更处理 |
| --- | --- | --- |
| 搜索与筛选 | 显示结果口径和活动条件；无权限对象不计数 | 失败保留条件；空结果可逐项清除 |
| 多选 | 默认选择当前已加载范围；全筛选结果需单独明确选择，冻结目标身份/修订 | 提交前复核权限与范围；逐项报告失败，不扩大到后来新增匹配项 |
| 排序 | 字段、方向及稳定次序可见；未排序字段不伪造箭头 | 不修改显示号/业务次序，失效字段提示移除 |
| 分组 | 标题、对象数、未知组及组内范围 | 切组不删除或复制事实，统计可回查 |
| 右键/更多 | 同一对象、选择和权限得到同一动作集 | 有键盘及触屏入口；取消回到原焦点 |
| 保存 | 草稿、提交中、服务器已保存、失败、冲突分别显示 | 保留草稿，不用刷新覆盖，重试检查修订 |
| 删除 | 可恢复删除与不可逆永久删除文字区分 | 永久删除列出对象/范围并明确确认，不给伪撤销 |

页面结构、表头关系、按钮名称与输入标签可读；DOM阅读顺序与视觉顺序一致。读表优先语义表格，只有明确的表格编辑模式采用完整键盘网格行为。焦点与选择分别表现；抽屉/对话框关闭返回触发对象，删除对象后定位合理邻项。
