# 知识类型、预设和自定义项的维护合同

版本：1.0，2026-10-05。状态：下一代设计提案，尚未实施。用户要求各类不能只有“类型”字段，必须包含或明确链接具体预设、自定义内容及其字段。本篇补足维护规则；初始选项不是已经批准的全部行业标准或全部产品名单。

入口：[总目录](KNOWLEDGE_CATALOG_STRUCTURE_2026-10-05.md)。本篇沿用[总纲字段语义](VNEXT_MAX_EXTENSIBILITY_REQUIREMENTS.md#201-字段类型null--unknown-与通用保存规则)、[知识基础合同](KNOWLEDGE_FOUNDATION_AND_EXTENSIBILITY_2026-10-05.md)和[权限合同](PERMISSION_RULES_2026-10-05.md)，不建立第二套字段服务、知识库或权限机制。

## 1. 每个小类必须给出什么

一个小类需要同时可读到：所属工种大类、专业范围、真实下级类型或资料分项、具体可选内容、各项适用字段、相关岗位、定义来源和自定义边界。只写“附件类型”“表现方式”“支持功能”，没有内容或有效入口，不能算完成。

| 层面 | 编写要求 | 不能代替它的内容 |
| --- | --- | --- |
| 知识小类 | 表达一种专业内容，如控光附件、镜头运动 | 器材品牌总库或组合标题 |
| 下级类型 | 类型确实属于本类，如反光罩下的标准罩、深抛反光罩 | 参数、用途、品牌、实际装配对象 |
| 独立维度 | 形状、材质、安装方式、光学作用分别列出 | 把所有组合都造为一个新类型 |
| 具体项 | 中文名称、唯一身份、清楚定义、适用字段及条件 | 一个含糊的“其他”文本框 |
| 字段 | 类型、单位、适用对象、空值语义、规范保存方式 | 只有显示名称、没有定义的字符串 |
| 岗位关联 | 从既有工种目录读取身份，写本字段用途和条件 | 自动授权、自动任职或默认唯一主责 |

独立概念仍使用有类型的知识关系。没有真正子类型的基础概念可以是叶节点；其定义入口写“共享定义”，不能把本概念再次放到自己的下级充数。一次引用需要显示完整大类和小类路径；路径是阅读归类，不代表业务所有权。

## 2. 四种维护方式

| 维护方式 | 可选内容来自哪里 | 自定义如何处理 |
| --- | --- | --- |
| 可扩展词表 | 本小类初始预设及有定义的新增项 | 创建稳定字典项，保留名称、定义、修订和适用范围；不能只保存任意拼接文本 |
| 规范数值或结构值 | 量、单位、参考系、范围和条件 | 可以输入规范值；常用数值只是快捷填入，不把焦距、角度、尺寸或时长做成封闭类型 |
| 固定来源引用 | 器材、软件、格式、业务对象、固定产物及其修订 | 缺对象时进入对应资料登记，不能用“自定义”冒充已有对象或已支持能力 |
| 受控业务口径 | 状态、方向、核验结果、空值语义等权威合同 | 普通字典编辑不能增加状态或改变跃迁；需要业务需求、合同更新及对应验收 |

四种维护方式是选择内容的规则，仍映射到总纲的枚举、字典引用、规范量和自由文本。对象引用遵守原领域的关系合同，不强行转换成知识字典。创作意图可以保留自由描述；自由描述不自动参与严格统计或兼容判断。

初始选项没有全选默认、没有自动选第一项、没有缺值兜底。未记录、明确未知、不适用、数值零和布尔否定分别保存。一个词表可以多选还是单选，按具体维度定义；有序动作使用有序引用，不能用多选代替时序。

## 3. 预设项和自定义项的资料字段

下面是对现有知识字典的字段需求，不是新增一级业务实体或已实施数据库列。技术名称待与统一字段服务登记后锁定；已存在的名称和身份复用。

| 中文字段 | 记录内容 | 约束 |
| --- | --- | --- |
| 稳定身份 | 不随中文名称或分类显示变化的字典项身份 | 历史、导入和业务选择引用身份；同名不自动合并 |
| 所属小类 | 明确工种大类、知识小类及定义位置 | 不能仅挂在“附件”“其他”总项下 |
| 上级类型 | 存在真实下级关系时指向所属类型 | 不允许循环；用途关联不是上级类型 |
| 中文名称 | 用户阅读名称 | 不只显示英文缩写；名称变化产生修订 |
| 英文检索名 | 有明确对应词时用于检索 | 缺少对应词可以未知，不编造翻译 |
| 别名 | 简称、同义写法、导入原词 | 歧义别名不能自动映射到唯一项 |
| 定义 | 本项表达什么、不表达什么 | 一项只表达一种类型或一个独立维度值 |
| 内容来源 | 初始预设或自定义 | 不等于官方核实、不等于授权等级 |
| 可用范围 | 原知识权限合同确定的资料可见范围 | 创建者不能通过改类型范围扩大资料访问权限 |
| 适用字段 | 继承的共同字段及本类型专属字段引用 | 各字段单独声明类型、单位、条件和岗位；不在备注藏字段 |
| 定义来源 | 来源资料、定位、修订、核验状态 | 自制器材说明不是官方事实；缺证据仍可保留明确未知 |
| 当前修订 | 本次定义的固定修订 | 被业务引用的解释不能随类型编辑无声漂移 |
| 生命周期 | 按知识对象原删除、恢复、永久删除规则 | 不增加通用归档动作；永久删除按原合同预览确认并清受控正文 |

## 4. 自定义内容的完整流转

1. 从实际所属小类进入，先检索预设和现有自定义项，显示定义、范围和修订。
2. 没有合适项时，明确选择新类型、新维度值或新型号资料。三者不混用。
3. 填中文名、定义和所属范围；继承共同字段，逐项补必要专属字段、类型、单位、条件及岗位用途。
4. 对歧义名称保留原文并选择明确类型。比如“深抛”必须分清反光罩或柔光箱；不能靠关键词直接判兼容。
5. 预览受影响的检索、当前引用、历史解释、导入映射和导出字段。有权限的操作者按已有修订及并发合同保存；冲突保留草稿，不覆盖他人修改。
6. 项目使用时固定字典身份及当时解释。知识定义更新可以提示变化，不能自动改变项目选择、镜头实际值、任务状态或已发布通告。
7. 调整分类或合并别名时显式选择映射；被正式引用的身份不直接覆盖成另一身份。普通删除停止新选择并按原规则保留历史；永久删除走原知识合同，不能承诺永久保留已要求清除的正文。

新增词表项复用知识维护权限和审计，不要求全站每个人都有编辑权，也不新建领用审批。项目内自定义是否可以贡献到更大知识范围仍按原贡献及验证规则，不因名称类似自动共享。

## 5. 附件类型、型号和装配分别管理

| 内容 | 保存什么 | 不能推出什么 |
| --- | --- | --- |
| 附件类型 | 标准罩、菲涅耳附件等定义及字段模板 | 对任意灯具的支持 |
| 附件型号 | 实际型号身份、安装点、专业规格和明确来源 | 所有同类产品都有同规格 |
| 自制附件资料 | 名称、用途、实际结构、已知条件、来源及未知项 | 官方型号、官方认证或无条件适配 |
| 支持记录 | 明确两端、功能、条件、必要部件、证据和修订 | 机械能连接就同时具有供电、光学或控制支持 |
| 项目配置 | 所选型号、类型引用、时段需求及数量 | 写回型号事实、形成库存或已准备好的事实 |

完整器材类型和字段入口见[D 类器材类型表](knowledge/D_EQUIPMENT_TYPES_2026-10-05.md)。具体品牌、型号、数值、直接配对和装配证据只进入[真实资料](REFERENCE_SEED_DATA_2026-10-05.md)或真实项目记录；本篇和分类分册不建立实际配对。

## 6. 导入、检索和导出

导入先识别所属小类、维度、原词、单位和来源位置，展示候选定义与解释；同名、简称和未证实词保持待选择。字段映射预览后支持添加、覆盖或保留原文；不将未识别值静默写入封闭业务状态，不自动建立支持关系。

检索同时支持中文、英文检索词、别名、所属小类、预设/自定义来源和明确适用字段。空宿主名单不匹配全部器材；自定义项不因检索命中而获得跨范围权限。

导出显示中文完整路径、字典身份及修订，连续量带单位；必要时保留导入原词和自定义定义。选型清单、型号规格和时段需求分开输出。分镜表或通告仅输出配置允许且用户有权查看的字段，不写免责声明。

## 7. 后续实现验收

| 场景 | 必须能证明的结果 |
| --- | --- |
| 控光附件查询 | 能读到标准罩、深抛反光罩、菲涅耳附件及其适用字段，也能进入自定义类型；没有孤立“附件类型”空入口 |
| 深抛简称导入 | 同时展示反光罩/柔光箱候选；保留原词，在预览明确选择后才提交 |
| 自制附件登记 | 能选择类型、填写未知安装条件和来源；不会自动出现官方核实或通用兼容 |
| 多维类型 | 镜头可同时是定焦、变形投影并具有近摄能力；不强迫三选一 |
| 连续数值 | 合法的非预设数值可以保存并计算；未知与零分别回读 |
| 岗位关联 | 每个专属字段有既有岗位身份和专业用途；无额外写权限授予 |
| 受控业务状态 | 普通自定义词表编辑不能新增“批准”“同步成功”等状态或绕过业务检查 |
| 定义变化 | 固定修订引用仍按原解释；迟到导入检查权限、修订和删除标记 |
| 删除 | 普通删除/恢复与永久删除按权威知识合同回读；不能借缓存重新显示已清正文 |
| 导出回读 | 中文路径、身份、修订、单位、自定义说明与输入一致；不把资料选择当执行事实 |

以上是待实现的验收要求。本轮只检查Markdown的分类、覆盖、引用和原资料保存，不将文档通过登记为产品验收完成。
