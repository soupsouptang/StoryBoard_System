## 1.2 岗位驱动专业知识

JOB_CATALOG 1.1 包含139个可任职岗位编号（与1.0的岗位行完全相同）。知识体系不复制岗位名称/职责行，而由[岗位驱动知识目录](ROLE_KNOWLEDGE_CATALOG_2026-10-05.md)使用稳定岗位编号建立专业知识域绑定，覆盖A项目管理与制片、B策划/内容/导演、C视觉设计与美术、D摄影/灯光/录音/现场、E出镜/表演/造型、F AE/MG/二维/合成、G三维/实时/三维视效、H剪辑/声音/成片/交付。

岗位检索至少可以返回：相关概念、工作输入、产出类型、上下游交接、专业原理/判断维度、质量关注点、相关官方器材/接口/兼容关系、软件适用能力范围、格式/色彩数据流、粗粒度时间校准及来源版本。这里的“方法”解释专业原理和生产关系，不提供逐步操作教程；Checklist继续只表达是否满足，不恢复SOP。

方案岗位和执行岗位必须保持知识分支。B14与G09a继续保留专业分支。一个现实人员可以同时关联多个岗位知识，但人员数量、工时和任务仍按原业务事实计算。

知识域可被多个岗位共享，岗位也可关联多个知识域；检索关联不产生项目任职、Task、权限或默认启用岗位。J系列状态以工种目录第3.2节为准，尤其J-04未确认前，岗位改名/拆分只能形成新目录版本并提示知识绑定复核，不能按显示名称自动迁移。

## 2. 贡献范围与权限

后台用户组保留团队归类方式。一个团队可以归类多个用户组，成员所属团队从统一组成员关系推导；知识模块不另建成员名单，不新造登录或项目授权系统。

新经验采集时，自动贡献到当时项目成员所属全部团队的并集。固定贡献团队身份、采集时间和当时的成员关系版本；同一团队去重。不是只按创建者，也不要求项目手动选一个团队。

成员以后加入或退出团队，只改变之后新经验的贡献范围，旧经验范围保持。例：采集时成员属于团队甲、乙，之后改为甲、丙，旧经验仍贡献甲、乙，新经验贡献甲、丙。原经验的修正保留该经验原范围；新的独立观察重新计算范围。不能用重算任务或搬组批量扩散旧经验。

没有可确认团队时只在项目内使用。项目管理者明确关闭或撤回贡献、来源被删除或永久删除时仍停止参与统计；这与成员换组不追溯是两件事。团队归类变更不自动迁移既有贡献，稳定团队身份删除后不可继续提供其汇总，处理剩余引用并失效相关结果。

团队仅获得合格去标识汇总。首版发布门槛为至少10个独立执行单位、至少3个项目；不满足时返回样本不足，不能提供能反推人员或客户的小组统计。原始回答、客户、未公开作品、联系人和项目正文始终按项目及答者权限隔离。读团队汇总检查当前团队权限，旧贡献范围保留不表示离组的人仍可读。

第15问已取消通用大库房、库存和预留，仅保留知识与时间段需求。取消库房不改变经验贡献或原始回答隔离。

### 2.1 贡献范围怎样持久化

E1-POLICY负责后台用户组及团队归类，K1-EXPERIENCE只保存贡献引用，不另建团队成员。团队身份稳定，用户组归类及成员关系带修订；跨组重复属于同一团队时去重。

“采集时”在首版指一次经验正式提交并被服务器接受的时点，提前打开问卷或保存本地草稿不固定范围。该命令在一致的身份权限修订下取得有效项目成员明确关联账号的有效组及团队，保存贡献团队集合、采集时间、关系来源修订和计算版本。无账号人员、未确认关联或无团队记录不按姓名推断。

拟议ExperienceContribution记录经验身份、范围修订和稳定团队身份，组合唯一；只保存必要引用，不复制人员名单、账号凭据或联系方式。经验修正沿原范围，新独立观察新算范围；移组和团队重分类事件只用于之后的记录，不重写旧范围。后台重算必须读取已保存的范围，不重新查当前成员团队扩散旧经验。

只有达到去标识与样本门槛的统计进入团队查询，贡献记录不授予原始回答读取权。团队阅读权限实时校验；撤回、来源删除或永久删除使相关汇总和迟到作业失效。团队删除保留无正文内部引用或删除标记用于拒绝旧结果，不能因旧团队名称再建而恢复授权。验收包含甲乙→甲丙换组、修正旧经验、重复提交、团队删除和撤回重算。

## 3. 来源、核验与处理方法

每条知识分别记录证据来源、核验状态、处理方式，不能把“厂商”“人工智能”“已验证”塞进同一个信用枚举。

| 记录 | 最小要求 |
| --- | --- |
| 来源 | 官方、厂商、行业资料、项目实际记录、主动回答或人工观察；保存允许的摘要、引用位置、版本及访问时间 |
| 核验 | 未核验、已核验、有争议、已撤回；保存核验人、依据和条件 |
| 处理 | 原始摘录、摘要、统计或人工智能辅助；保存方法和服务版本 |

数值带单位、测量条件、适用型号和资料版本，未知不填零。额定功耗、实测耗电和输出光照分开。互相冲突的资料保留来源和适用条件，不能以最后录入覆盖反证。

只保存允许的必要结构化事实和摘要，不复制整本手册或项目正文。设备示例只说明结构；正式资料需核对原始页面或手册。型号别名帮助搜索，不合并实物身份。

人工智能生成先留候选区。必须有独立资料或实际记录，经统一权限和用户组系统授权的维护动作核验后，才能按真实来源进入正式知识，保留辅助生成过程。接受一条项目建议不等于完成知识核验，人工智能不能用自己输出证明自己。

## 4. 粗粒度时间经验采集

经验采集只服务预计时长校准，不建立常见问题、故障原因或解决方案知识库。优先直接读取 Task、ScheduleItem、Move、Post 等原业务模块已经确认的 Actual；只有实际时长缺失、明显不完整或只能获得粗粒度范围时，才允许向相关用户询问简短时间信息。

允许的首批问题仅围绕：

- 某 Scene / Task / Move / Post 工作大约实际用了多久；
- Setup / Shoot / Move / Post 等粗粒度阶段各用了多久；
- 无法精确提供时选择一个时间范围。

不询问“哪里卡了”“为什么超时”“哪个设备不好用”“怎么解决”“最佳设置是什么”。不建立问题排序/故障题库，不记录个人能力评分。

同一 source object + revision + metric 的重复采集只形成一个 ExperienceObservation。多人对同一执行事实给出的时间不能重复计成多个独立执行样本；Actual 被更正时生成新 observation revision，并使旧统计过期。

## 6. 汇总、估计与验证

先确定独立样本单位。一套共用布光被六个镜头使用算一次执行；同事件重试、多人回答、相同文件副本不增加实测样本。不同工序、单位或执行不能混入同一个统计组。

汇总保存条件、单位、时间范围、参与观察版本、排除原因、样本数、独立执行数、项目数、缺失量、实测量、自报量、中位数、第七十五百分位、方法版本和计算时间。使用成熟统计库，固定分位数方法和合成输入，保证可复现。

零、缺失、取消、异常分别处理。异常排除需明确方法和理由，原记录保留；实测与自报分组或说明权重。第七十五百分位表示经验分布位置，不是75%置信度，不能仅凭样本多就标高可信。

估计方案保存不可变计算版本、统计来源、条件匹配、缺失处理、算法和适用范围。按项目及时间留出验证，不能把同一次执行的不同回答随机拆到训练和验证两边。记录平均绝对误差、实际超预算率、覆盖率和分组误差，与原计划比较。不足时返回样本不足，不产伪精确时长。

新统计不改已确认计划、实际或已发布通告。来源撤回、永久删除使结果过期；重算形成新版本，失败明确不可用，旧缓存不能继续冒充有效建议。

## 7. 时间校准建议

首版“自学习”只表示粗粒度时间统计校准，不建立自适应问题池或常见问题排序。EstimateProfile 依据受权、去重、满足样本门槛的 Actual / 粗粒度时间观察形成不可变版本。

时间建议固定请求者权限、目标项目及对象版本、估计版本、匹配条件、缺项和候选时长。接受建议后仍经原业务命令更新未来计划；知识模块不直接写 Task/Schedule 事实。

知识关系只在真实检索需要时建立，限知识概念、官方型号、软件能力范围、兼容关系和岗位知识绑定。项目人员、Scene、Task、Schedule 和实际 Resource 仍归原业务模块。

## 8. 型号、兼容关系、软件范围与时间段需求

设备与软件基础模型统一遵循[知识库基础合同](KNOWLEDGE_FOUNDATION_AND_EXTENSIBILITY_2026-10-05.md)。

设备型号、变体、模组、模式、规格、接口与配件各自拥有明确资料。权威字段字典见[器材字段合同](EQUIPMENT_REFERENCE_FIELD_CONTRACT_2026-10-05.md)；型号不把变体或单一来源地址混成固定属性。官方规格参与筛选、查询和兼容判断；人工备注使用独立 EquipmentNote，不覆盖官方 SpecificationValue，也不作为兼容自动判断依据。新型号通过 EquipmentCategory + SpecificationDefinition 录入，不能要求为每个新品修改主业务表。

兼容关系使用 typed CompatibilityRelation，至少区分 DIRECT_COMPATIBLE、REQUIRES_ADAPTER、INCOMPATIBLE、CONDITIONAL_COMPATIBLE。类别文档只定义接口、适用范围、必要中间件、功能和证据字段；真实连接样例只放数据样例，逐端标明所属大类、型号、条件和来源。原生接口不能被转接结果替代；正式兼容以厂商证据及全部必要条件为准。

软件只保存 SoftwareProduct / version scope 到 Capability Domain 的适配关系，例如某三维软件对 THREE_D_MODELING 为 PRIMARY，而对 EDITING 为 NOT_SUPPORTED 或受限。软件知识不保存按钮路径、快捷键、插件教程或逐版本新功能文章。

取消通用大库房，仅保留某时间段的拍摄需求。Scene、Shot及导入结果提供型号、数量和来源；缺值提示未知，不能根据知识库或常用设备猜数量。知识中的兼容关系也不等于项目实际拥有设备或转接件。

## 10. 历史、删除、导入导出

知识修订、经验与回答、估计版本独立于项目创作版本。项目只固定接受建议的必要引用与命令回执；人物私人资料、整库知识或他项目样本不夹带进工程文件。

正式来源和产物保存到明确删除；临时预览默认24小时，可重建下载工件默认7天，项目可缩短临时留存。临时到期不删除正式来源。

明确撤回贡献解除统计参与，不误删原项目事实。永久删除先预览和确认，清当前及历史正文、来源摘录、索引缓存、统计样本、作业暂存、建议和受控下载，仅留无正文内部删除标记。旧撤销、导入、作业和备份恢复不能复活。

导入受权知识引用只携必要身份、版本及允许摘要，不自动增加正式知识、用户权限、团队或库存。别处生成的文件不是本项目授权证明。
