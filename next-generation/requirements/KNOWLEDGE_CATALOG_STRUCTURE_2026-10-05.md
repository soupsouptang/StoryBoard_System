# 知识目录规则

版本：1.1，2026-10-05。状态：下一代分类规划，尚未实现。A–H岗位大类按用户确认保留；知识类别、主题、组件和参考对象独立拆分。本文件只定义类别和入口，不填写真实产品或直接配对。

## 1. 分类规则

- 分类标题表达一种内容，不使用“甲与乙”“甲、乙及丙”等清单式标题。相关性通过具名关系表示。
- 真正的下级类型可以在一类中展开，例如运镜中的摇、移、推、拉；彼此相关的构图、观察角度、运镜不能合成一项。
- 每个主题、组件和字段都有中文名称；英文只作为术语、别名或字段键。
- 数值区间是一种参数，尺寸向量也是一种参数，但必须展开其内部维度。不同参数不能借结构化字段名堆在一起。
- 所有知识正文只有一个权威维护位置；岗位入口引用正文，不复制。
- 器材浏览按照“大类 → 该类品牌 → 型号 → 对应项 → 字段”展开；这是一条浏览路径，不增加知识分类实体深度。
- 各产品事实、配件名单和真实组合只进入[真实资料](REFERENCE_SEED_DATA_2026-10-05.md)。分类本身不推断安装适配。
- 分类最多四级：知识库 → 专业域 → 组件 → 可选细项。主题、型号和格式通过引用连接，不塞成第五级。

## 28. 岗位专业关联

A–H大类保持原样。岗位稳定编号和任职定义不变；知识域作为岗位检索范围，下列具体知识组件独立维护。岗位和知识关联不创建权限、任职或项目任务。

入口：岗位 → 专业域 → 独立组件 → 共享主题或本专业资料。转到其他专业时，先显示目标专业类别，再显示独立主题或器材类别；不从一个品牌总项跳到其他专业参数。

| 关联字段 | 中文含义 |
| --- | --- |
| `source_category_id` | 起点类别 |
| `source_id` | 起点主题或组件 |
| `target_category_id` | 目标类别 |
| `target_id` | 目标主题、组件或参考对象 |
| `relation_type` | 关系类型 |
| `reason_zh` | 中文关联原因 |
| `direction` | 关系方向 |
| `conditions` | 成立条件 |
| `source_revision` | 起点修订 |
| `target_revision` | 目标修订 |
| `source_reference_ids` | 来源引用 |

例如构图设计引用构图知识，运镜设计引用运镜知识，二者协同通过关系解释；不因此写成“构图与运镜”分类。实际型号、安装组合和证据只见真实资料。
