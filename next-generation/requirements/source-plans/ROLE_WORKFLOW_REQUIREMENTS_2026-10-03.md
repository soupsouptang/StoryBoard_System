## 2. 账号、人员、岗位与剧情角色

| 对象 | 含义 | 必须分开的行为 |
| --- | --- | --- |
| 登录账号 User | 谁登录、是否启用、有什么权限 | 停用账号不删除现实人员和已经发生的制作记录 |
| 现实人员 Person | 项目中的演员、配音或工作人员，可没有账号 | 同名不合并；每个项目身份独立，账号关联要明确建立 |
| 岗位任职 | 一个人在项目、场景、镜头或任务中的职责 | 一人可多岗、一岗可多人；岗位名称不授予权限 |
| 剧情角色 Character | 作品中的人物或声音角色 | 剧情角色不是账号，也不是任务负责人 |
| 选角关系 Casting | 候选或确定由谁出演某个角色 | 候选不算已经确定，同一演员可饰多个角色 |

项目独立授权，明确拒绝优先；组织容器不传递项目权限。人员跨项目冲突只依据明确关联的共享身份，不按姓名、邮箱或型号猜测。每个任务只有一名主责，可有多名协作；这不限制某个岗位有多名任职人员。

私人联系资料单独授权，不默认采集证件、合同、薪酬，不进入普通看板、内容快照和交付附件。

## 3. 场景与镜头怎样关联

项目分别拥有场景和镜头，两者通过多对多关系连接。一个镜头可以没有场景，也可关联多个场景；最多一个主场景，主场景仅用于默认展示。镜头篇章保持独立，关联场景属于不同篇章时提示差异，不自动改归属。场景内镜头顺序与项目镜头顺序分别保存。

镜头动态继承所有关联场景的演员、场地和设备要求。用户可逐项增补、排除、替换或恢复继承；其余项继续随场景更新。有效要求可从来源和手动覆盖重新计算，不复制成另一套相互覆盖的数据。

继承的是“需要什么”，不表示演员已经出镜、器材已经登记或拍摄已经完成。实际出演、任务执行和资源需求各由原模块确认。恢复继承读取场景当前要求；同名的新来源不能冒充已经删除的原来源。

地点、内外景、昼夜优先使用镜头明确值，否则使用主场景值。其他关联场景不同则显示差异；没有主场景或必要信息缺失时提示待确认。对白先保留现有文本和明确角色引用；没有真实多说话人编辑入口前不另建空白对白结构。

删除场景不删除关联镜头、现实人员或独立型号参考。所有连接校验所属项目和当前权限；镜号重排不改变稳定身份。

## 4. 任务和交接

镜头制作步骤表达拍摄、剪辑、合成等制作工艺；独立任务表达场地确认、准备、拍摄、备份、返工等执行动作。任务引用原制作状态和审阅结果，不保存第二份“全镜头批准”状态。

工作流模板发布后固定版本。项目可自行建立空工作流和真实节点，不因尚无默认工种模板停住实现；模板升级不重写进行中的实例。

| 操作 | 条件和结果 |
| --- | --- |
| 分派或转派 | 有操作权限；保留一名主责、多名协作及变更记录 |
| 开始 | 主责已确定，必需输入和前置依赖就绪 |
| 提交产物 | 固定素材版本、提交者和所用输入，不能只保存“最新素材”链接 |
| 确认交接 | 核验接收人、产物版本和任务规则；需要独立审片时不能自确认 |
| 跳过 | 管理权限和理由，仍检查下游必需输入；不能伪造审片批准 |
| 返工或更正 | 保留已经发生的执行和交接，使受影响的后续输入重新核对 |

首版依赖表示“前项完成后后项可开始”。重复边、自身依赖、跨项目边和循环依赖拒绝写入。并发建立依赖也必须验证整个受影响图；共享场景任务只建立一次，不因被六个镜头引用就执行六次。

任务的可开始、受阻、输入过期由事实推导。正常制作联动自动更新可成立的未来安排；锁定、缺输入或缺权限的例外说明原因、负责人和重试办法。已发生的实际执行和旧版已发布通告不随预测改写。

示例模板只作为可选配置：实拍可从准备到拍摄、校验和剪辑；合成可分设计、输出、独立审片与返工；声音可从文稿到录音或真实语音合成、校时和交付。不能将示例当作每个项目强制节点。

## 5. 灯光器材与时间段需求

第15问取消通用大库房，只保留知识库与按时间段看需要什么。场景要求、镜头字段及导入结果保留型号、数量、来源和识别状态，缺值不猜。需求识别不生成库存。

同一时间独立需求相加，明确共用后只计一次，不同时间分别汇总。器材知识仅型号与基础知识，不提供使用方法；需求关联已有排期，未排期另列，人员与场地仍在原排期模块。详见[资源需求](https://github.com/soupsouptang/StoryBoard_System/blob/493bbb24e92f42315ad54e451629ef005fd5ab00/storyboard-system/docs/RESOURCE_TIME_REQUIREMENTS_2026-10-04.md)。项目原权限继续生效，没有库房资格、预留或领用审批。

## 6. 岗位视图和导出视图

| 使用者 | 要看什么 | 操作从哪里执行 |
| --- | --- | --- |
| 我的工作 | 本人任务、可开始项、受阻原因、期限和交接对象 | 原任务命令，并能定位原场景、镜头或审阅对象 |
| 导演、制片 | 场景准备、镜头、人员需求、依赖、资源缺口和拍摄日 | 原项目、场景、任务、排期模块 |
| 摄影、灯光 | 摄影字段、灯光画板、器材型号与所选时段需求 | 原镜头、画板和资源模块，不复制编辑后端 |
| 演员、选角、现场 | 角色、确定出演人员、场景要求和允许查看的通告 | 原人员、选角与出演关系 |
| 剪辑、合成、声音 | 固定输入素材、输出版本、返工和审片意见 | 原素材、任务、旁白与审阅模块 |
| 导出使用者 | 本次接收方允许得到的范围、字段、产物和格式 | 统一授权导出，不从浏览器卡片拼文件 |

任务卡、角色看板、统计都是同一套事实的查询结果。无数据、无权限、加载失败、确无待办要分别显示。多个岗位可显示同一镜头，但不能出现互不一致的镜头状态。

进入同一个共享视图的人同步列显示、顺序、宽度、行高、筛选、排序和分组；个人选中、光标、草稿、页面选择和滚动独立。临时输入可本地预览，确认后服务器保存并广播。影响共享结果的筛选不能又保存成个人权威配置。不同视图不会强迫所有人跳转。

岗位视图、共享配置、工作流模板和导出模板各自保存配置；导出字段仍经过权限与本次选择检查。没有审阅标记时，表格评论列隐藏，不删除审阅历史。

## 7. 数据看板的计算规则

新指标不能未经单独决定替换现有四项制作概览。每项返回分子、分母、计算范围、时间、来源版本和可下钻对象；权限受限时说明是可见范围。

| 指标 | 计算要求 |
| --- | --- |
| 镜头完成率 | 按活动镜头身份去重；回收镜头不计，零分母显示暂无镜头 |
| 岗位任务完成率 | 共享任务只计一次；取消排除，跳过和过期单列，不冒充完成 |
| 可开始、受阻、超期 | 按任务去重；多种受阻原因可分组，无期限不算超期 |
| 演出准备情况 | 按角色需求计，候选演员不增加分母 |
| 待审产物 | 固定提交和素材版本；多个评论不算多个产物 |
| 交付就绪情况 | 产物、有效审阅、授权和输入时效分别检查 |
| 器材与道具需求 | 按型号、来源和时间段汇总，独立相加、明确共用；缺型号数量或未排期单列，不显示库存不足结论 |

AE 与 VFX 重叠是制作任务口径，不得相加冒充全项目镜头数。同一明确共用需求不能因关联多个镜头重复累计。

## 8. 权限、历史和交付

列表、搜索、计数、详情、媒体、实时连接、历史、文件预览和下载使用同一有效权限。岗位名称不授予项目权限，隐藏按钮不能替代鉴权。库房已取消，资源需求沿原项目权限，无额外库存资格。权限撤销后重新校验运行中的任务和旧下载入口。

导出对象取授权范围与本次选择的交集；导出字段取活动字段、对象与字段权限、本次勾选和分享限制的交集。PDF 正文、Word、表格、预览、工程二维码、附件和便携包共用这份投影。排除联系人或图片后不能在隐藏数据、附件、文件名中继续夹带。

| 数据 | 保存在哪类历史中 |
| --- | --- |
| 角色、选角、场景要求、镜头明确出演、灯光内容 | 整个项目创作版本，保留镜头比较入口 |
| 人员资料、账号链接、成员授权 | 独立授权和活动记录 |
| 任务实际执行、交接、审阅、通告发布 | 各模块的独立记录；更正不抹去已经发生的事实 |
| 共享视图、导出配置、情绪板 | 不进入创作版本；可撤销操作复用唯一项目历史服务 |
| 时间段资源汇总 | 从原需求与排期查询，无库存和预留历史 |

可撤销的项目命令复用现有 HistoryService，失败不移动游标，他人的后来修改不能被旧撤销覆盖。永久删除需确认，不可撤销；受控旧快照、缓存、导入或异步结果不能复活已永久删除内容。

## 9. 实施顺序和验收

按[机器执行清单](https://github.com/soupsouptang/StoryBoard_System/blob/493bbb24e92f42315ad54e451629ef005fd5ab00/storyboard-system/docs/extensibility_execution_plan_2026-10-04.json)领取独立工作包。先完成身份、权限和命令基础，再做场景、人员、任务、资源、排期和导出；不同模块在依赖满足后可并行。现有画板、导入、工程导出的未验收项仍要单独补证据。

| 编号 | 必须实际验证 |
| --- | --- |
| RW-01 身份 | 无账号演员、同名两人、一人多岗、一演员多角；不误合并、不自动授权 |
| RW-02 场景 | 多场景需求动态继承和逐项覆盖；实际出演不从需求推定；主值显示差异；删除一场景不删共享镜头 |
| RW-03 任务依赖 | 分支、汇合、共享任务、并发反向边；无循环，模板升级不重写在途任务 |
| RW-04 交接 | 固定输入输出版本；相关上游修改使输入过期，无关视图不影响；独立审片不能自确认 |
| RW-05 多用户 | 并发修改只接受有效版本，失败保留草稿；同一请求重试不重复写入 |
| RW-06 统计 | 重叠制作方式、共享任务、取消、过期、零分母；下钻集合与数字一致 |
| RW-07 权限 | 无权直接访问、搜索、计数、媒体、历史和导出均受控；撤销后旧产物不可继续访问 |
| RW-08 历史 | 内容、审阅、配置和排期分开；情绪板可撤销；永久删除不能由旧版本恢复 |
| RW-09 新页 | 真实桌面横屏验证读写、保存失败、冲突、键盘、焦点、明暗和动画；已有页面不覆盖 |
| RW-10 资源 | 识别保留来源候选；型号数量缺值、共用、分时、未排期、权限和不重复汇总 |

本文已移除失效的“暂不继承”“权限待定”“个人筛选同步例外”等提案。项目成员名单、器材实际数量、工作窗口、默认工种模板和新页位置仍由实际配置或指定页面负责人提供，不能编造。本轮只完成需求修订，不声明上述模块已经通过验收。
