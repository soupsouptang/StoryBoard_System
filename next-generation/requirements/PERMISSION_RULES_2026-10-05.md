## 1. 身份与范围（已确认）

| 身份 | 范围 |
| --- | --- |
| 个人用户 | 自己的账号、能力档案及个人项目 |
| 普通团队成员 | 所加入团队内的组织列表、展示技能和本人项目关系 |
| 项目成员 | 所参与项目的内容查看，分配给自己的工作编辑 |
| 独立团队管理员 | 唯一团队管理权，本团队所有项目管理 |
| Agency所属团队管理员 | 唯一本团队内部管理及本团队全部项目；不掌握所属团队建立/解散或脱离Agency功能 |
| Agency管理员 | 固定最高管理账号，所属全部团队及其内部项目；指派/改派团队管理员，创建/解散所属团队 |
| 系统最高管理员/知识后台 | 通过统一系统权限和用户组授权的知识维护动作管理岗位定义，不另设知识库专用角色；本轮未据此自动授予所有业务项目内容访问权 |

一个账号在不同范围具有不同身份；在甲团队拥有管理权，不因此管理乙团队。一名团队成员可有多项能力和工作岗位，能力名称不授予管理权。

每团队唯一管理员，独立团队管理权整体移交，无部分授权或额外管理员。Agency不移交；其固定管理员可以指派、改派所属团队管理员。

## 2. 个人技能与团队展示（已确认）

| 动作 | 用户本人 | 本团队管理员 | 结果 |
| --- | --- | --- | --- |
| 从知识库选择、增删个人技能 | 可以 | 不能代替用户自行增删 | 自行修改，不需团队批准 |
| 提交首次/新增团队展示 | 可以 | 审批申请 | 批准后才可用于工作分配 |
| 停止在某团队展示技能 | 可以 | 不能代替用户自行增删 | 直接生效，通知管理员 |
| 删除个人技能后的团队同步 | 本人触发 | 接收通知 | 所有已加入团队同步移除展示 |
| 查看完整个人能力 | 本人可以 | 可以查看本团队成员拥有但未展示的能力 | 普通成员只能互看本团队有效展示 |
| 修改知识库岗位定义 | 不可以 | 不可以 | 系统最高管理员/后台知识库维护 |
| 选择团队岗位需求 | 以对应管理身份操作 | 可以 | 需求选择不改变他人个人能力，不创建知识库新定义 |

新增展示申请未批准或被拒绝，原有效展示保持不变。管理员看见未展示能力，不表示可据此分派工作。

## 3. 团队和Agency组织管理（已确认）

| 动作 | 独立团队 | Agency所属团队 |
| --- | --- | --- |
| 创建团队 | 个人账号可创建，检查Agency条件 | Agency管理员操作 |
| 团队管理权变更 | 当前管理员移交给现有成员，检查接收人的管理团队数量及Agency条件 | Agency管理员指派/改派本团队成员 |
| 管理员本人退出 | 先完成管理权移交 | 先按Agency指派规则完成接任，再办理退出 |
| 成员加入 | 邀请接受或有效串号自动加入，检查人数/Agency条件 | 沿同一加入方式，检查每队200人上限 |
| 退出/移除 | 团队管理员审批，按有效展示能力交接 | 团队内部管理规则适用；Agency管理员拥有所属内部管理权 |
| 主动脱离Agency | 不适用 | 不允许 |
| 所属团队建立/解散 | Agency范围不适用；独立团队一般主动解散入口细则未单独确定 | 由Agency管理员管理，团队管理员不能自行操作 |
| Agency解散 | 不适用 | 仅Agency固定管理员决定并通知成员，无需成员同意 |

Agency整体解散后，由其他管理员管理的团队是否保留，按已确认的特殊流程由各团队管理员决定；这不赋予Agency存续时的自行脱离权限。

管理权移交不改变项目工作责任。退出获批可离队，即使无人接手；缺口持续标红，业务流转不中断。

## 4. 项目归属、创建与接收（已确认）

1. 用户可以创建个人项目，归自己管理；团队项目由对应管理员创建。
2. 创建项目与组队没有先后顺序。
3. 个人项目转入团队，由目标团队管理员确认接收；确认前保持原归属。
4. 接收后直接成为团队项目，按团队/Agency管理，不再额外办理一次管理权转交。
5. 项目具有唯一归属，不同时属于多个团队或Agency；分享不产生平行项目或重复归属。
6. 未决定个人转入团队之外的跨团队整体转移或退回个人流程；不擅自开放。

## 5. 项目查看与工作编辑（已确认概要）

| 使用者 | 项目列表 | 项目内容 | 编辑/管理 |
| --- | --- | --- | --- |
| 个人项目管理者 | 本人个人项目 | 可查看 | 管理自己的个人项目 |
| 团队成员，未参与目标项目 | 查看全部时可列出并标记 | 不可进入内容 | 不可据团队成员身份编辑 |
| 目标项目成员 | 默认可见本人参与项目 | 可查看完整项目 | 仅编辑分配给自己的工作 |
| 团队管理员 | 本团队全部项目 | 可进入全部 | 管理本团队全部项目 |
| Agency管理员 | 所属团队全部项目 | 可进入全部 | 管理所属全部团队及项目 |
| 已离队用户 | 个人历史摘要 | 需另行授权 | 原团队/项目关系不自动保留编辑权 |

未参与项目的列表字段和缩略图范围仍待细化。跨团队个人关系仅本人管理/查看，Agency所属管理关系适用本文件的明确管理范围。

“完整项目查看”与导出、下载、分享、删除等动作分别判定；本轮没有把所有动作自动赋给普通项目成员。

## 6. 工作分配与技能变化（已确认）

管理员依据成员在本团队最新、有效展示的技能分配、调整工作，操作后通知用户；已有项目新增工作也可直接分配，无需本人再申报。

成员自行申请增减负责工作时，管理员批准后才修改正式责任；等待/拒绝时保持。分配和交接不能使用未展示、未批准能力。

删除个人能力或停止展示，不自动修改已完成/正在进行项目原分工。新项目和已有项目新增分工用最新有效技能。管理身份移交也不自动改变项目职责。

## 7. 解散、历史与归档（已确认概要）

团队解散后项目及历史归档，停止团队协作，内容保留。Agency解散时与固定管理员同管理员的团队一并解散；其他团队按保留决定及Agency条件处理。

原管理账号按归档规则处理后续访问、导出。所有成员保留个人历史摘要，摘要不授予项目内容访问权。历史责任与执行记录不因退出、技能变化或组织解散清除。

本次未授权永久删除项目/媒体，也未决定归档后恢复、编辑或跨账号继承的细节。
