# FrameForge UI 一致性规则与验收

本文把当前控件库和样式中的共用规则整理成后续迁移与验收基线。最新用户提供的 **374px 手机截图**作为窄屏问题的复现基准；截图不复制进仓库，也不以截图路径作为依赖。截图中可见的布局问题，应在同尺寸视口复现、修复并做前后对比。

## 当前实现依据

- `src/workspace/theme.css` 定义深浅色共用 token、`--field-height`、`--field-radius`、`--toolbar-height`、层级和动效 token；共享组件使用 `.ffui-button`、`.ffui-input`、`.ffui-select`、`.ffui-dialog` 等类。该文件还规定了桌面工具栏、`max-width: 1100px` 和 `max-width: 767px` 的响应行为。
- `static/field-system.css` 把 native input、textarea、select、contenteditable 和 inline editors 统一进 FieldShell，使用 `--surface-editor`、`--border-editor-active`、`--field-height`、`--field-padding-x` 等 token；另有 property row 和富文本浮动工具栏规则。
- `static/workspace-flow-pages.css` 统一旧页面和 React 弹窗/按钮外观，包含检查器字段、表格首列、项目/资产/脚本/审阅页面规则，以及 `max-width: 720px` 的辅助页面响应样式。
- `packages/ui/src/index.tsx` 是共享 React 控件入口：Button/IconButton、Input/TextArea/Field/Select、Segmented、Checkbox、Popover/Menu/Modal 和 SortableList。底层使用 Radix UI、Lucide 图标与 dnd-kit；业务组件应优先组合这些入口，减少页面各自造一套交互。
- 目前并非所有页面已迁移到 `packages/ui`：主题文件存在 legacy compatibility aliases，flow CSS 仍覆盖旧 `.btn` 和 native dialog。新增样式应使用现有 token；迁移时逐一消除旧规则，避免追加另一层覆盖。

## 统一规则

### 按钮

1. 新页面使用 `Button` 或 `IconButton`，并明确 primary、secondary、ghost、danger 语义。相同动作在同一流程保持相同层级和文案；删除等破坏性动作使用 danger 并提供明确确认。
2. 图标按钮必须有可访问名称；工具栏不能仅靠 hover tooltip 才说明动作。主要动作保留文本，空间受限的次要动作才允许折叠为图标，并可通过名称/提示访问。
3. 桌面参考尺寸为 `theme.css` 中 `.ffui-button` 的 32px 高；767px 以下样式提高到 36px。374px 手机场景验收时，主要触控动作目标应达到至少 44×44 CSS px，或提供等效的可触控间距，不让相邻按钮难以分辨/点击。
4. 使用 `:focus-visible` 可见焦点、disabled 状态和 pressed/selected 状态；不能只用颜色表达状态。图标、文本、背景要在深色和浅色主题中可辨。

### 输入框与字段

1. 表单优先用 `Field` + `Input`/`TextArea`/`Select`；inline/native 字段仍复用 `field-system.css` 的 FieldShell token 和状态，不另造不同的边框、圆角、占位符或焦点规则。
2. 标签与控件左边缘对齐，标签放在控件上方或一致的标签-值列中；同一表单不要在字段之间切换左对齐、居中和右对齐。帮助/错误文字紧邻字段，并在窄屏下可换行。
3. 宽度容器允许收缩：字段、property value、长项目名均设置合理的 `min-width: 0` 并允许长内容换行。输入值不能因固定标签列而被挤到不可编辑宽度。
4. 延续现有 40px 字段基准、`--field-radius` 与 focus/error/disabled/read-only 语义。浮动格式工具栏可以横向滚动，但应保持按键的可见焦点和不被视口裁切。

### 弹窗、菜单和浮层

1. 可复用弹窗使用 `Modal` 或 Radix Dialog，菜单和选择器使用组件库 Portal/collision handling；不要自行覆盖 Escape 关闭、焦点回收、焦点陷阱或点击遮罩规则。
2. React `.ffui-dialog` 与 native `dialog.standard-dialog` 使用统一 surface、边框、圆角、标题/关闭按钮、正文和 footer 间距。弹窗内容滚动时，页面背景不应同时横向/纵向滚动。
3. 现有 `.ffui-dialog` 宽度为 `min(560px, calc(100vw - 24px))`，高度上限受 `100dvh` 限制；窄屏还将 padding 调为 16px。验收时确认标题、表单、错误提示、取消/确认按钮全部可见或可滚动到，不被软键盘/底部浏览器区域遮住。
4. 菜单、tooltip、toast、编辑工具栏和弹窗遵循 `theme.css` 的 z-index token 层级，不以任意大值解决遮挡。

### 箭头和方向

1. 使用 Lucide 的语义图标并统一方向：返回/上一步向左，下一步/进入向右，收起向上，展开向下。下拉选择控件的 `ChevronDown` 与现有 `Select` 实现保持一致。
2. 排序箭头表示真实升序/降序；时间线、画布、分页及版本比较的方向必须与实际移动一致。图标旋转时同步 aria-label 和可访问状态，不能只翻转图形。
3. 中文 LTR 页面以可视阅读顺序排列图标、文案和状态；若将来支持 RTL，只镜像表达阅读/移动方向的图标，不镜像播放、旋转、时间顺序或物理空间方向。
4. 箭头/chevron 的出现与否应有明确含义：可展开项显示展开状态，不可展开的普通按钮不要添加误导性的箭头。

### 文案和对齐

1. 中文操作使用“动词 + 对象”，并在同一流程保持命名一致；确认按钮说清结果，取消与关闭区分清楚。窄屏隐藏图标旁文字时，必须保留 `aria-label`，关键任务不能只靠无法发现的 tooltip。
2. 标题、说明、字段标签、数据值、按钮文案各自采用稳定的对齐和层级。数值/时码保留 tabular numerals；说明文字左对齐且可换行，不用全局居中来掩盖空间问题。
3. 表头和对应列值对齐；空状态与加载态在内容区域内居中，不影响整页/表单的标题对齐。长文案可以换行或省略并提供可访问完整值，禁止让它撑宽页面。

## 374px 手机与窄屏验收

使用浏览器 **374×至少 740 CSS px** 视口重新打开截图中的页面/状态，并分别检查深色与浅色主题。`theme.css` 当前 767px breakpoint 会折叠顶部信息、换行工具栏、缩窄次要按钮；`workspace-flow-pages.css` 在 720px breakpoint 处理辅助页面、对话框、脚本列表。两处规则都必须一并验证。

| 区域 | 验收点 |
| --- | --- |
| 整页 | 页面无意外水平溢出；`document.documentElement.scrollWidth` 不大于 `clientWidth`。允许镜头表/时间线/画布内部明确的横向滚动，不允许它们把整页撑宽。无 sticky header、浮层或 bottom safe area 遮住主要内容。 |
| 项目头部 | 项目名、多协作状态和主要菜单仍可访问；长标题截断或换行但不压住头像/操作。菜单打开后完全落在 374px 可见区域。 |
| 工具区 | 视图切换、搜索、列/筛选等入口均能找到。次要按钮可图标化，但每个图标有名称；按钮不重叠、不被裁切，触控目标及间隔满足手机操作。工具区可以分组换行/折叠，不应将关键动作排到水平视口之外。 |
| 镜头表 | 表格在自身容器内水平滚动；首列/镜头选择不被粘性表头遮挡，选中、编辑、拖动不误触。初始视口能辨认镜头编号与至少一个核心字段；编辑控件可聚焦且不会因页面级滚动丢失焦点。 |
| 字段和检查器 | 128px 左右的固定属性标签列在窄屏不会挤压值列；允许变为上下布局。字段、按钮和错误文案不发生横向裁切，键盘弹起后当前输入框和提交动作可滚动到。 |
| 弹窗/菜单 | 宽度遵守视口边距，正文可滚动，footer 操作可见；打开菜单/选择器后不越界，关闭按钮与遮罩/键盘行为稳定。 |
| 用户截图回归 | 将最新 374px 手机截图所示页面与修复后截图并排比较，先复现其拥挤/裁切位置，再确认空间分配已解决；截图只作验收基准，不把临时文件路径写进测试或文档。 |

## 画布与分镜面板专项验收

1. **分镜板与画布布局**：在桌面、374px 手机以及手机横屏打开同一分镜。画布比例和内容不被 CSS 拉伸；属性检查器可折叠/切换，画布最小有效工作区仍可见；面板滚动不带动画布坐标。
2. **工具栏**：全部工具有可读名称/选中态；窄屏工具分组可横向滚动或折叠，当前工具指示不被裁掉。工具栏和弹窗 z-index 正确，不盖住必要的保存/撤销状态。
3. **触控手势**：支持点选、拖动对象、画布平移、缩放和滚动画布；这些手势互不误触。拖动句柄遵循 dnd-kit/`touch-action` 设计，触控命中范围满足手机使用。
4. **箭头/方向**：画布平移、上/下一格、前后镜头、撤销/重做的图标和实际结果一致；操作后焦点/选择仍落在对应对象上。
5. **边界与恢复**：缩放、平移及旋转（若该工具提供）不会让对象离开可恢复区域；撤销/重做、保存/重载后对象位置与层级一致，切换 viewport 不丢失内容。
6. **协作状态**：多人光标/选中框使用可辨颜色和名称；手机窄屏不会挡住画布中心或工具入口，离线/同步中状态不依赖颜色单独表达。

## 后续实现与验收方式

新增 UI 先只使用 `packages/ui` 控件及 `theme.css` token；需要适配旧页面时在共享兼容层补规则，并标注删除旧选择器的迁移条件。将组件样式和业务结构分开，不在页面 JSX/模板上叠加局部 magic values。

每次 UI 改动至少记录：变更页面和状态、374px 截图前后对比、桌面基准视口、深浅主题、键盘/触控路径、横向溢出测量，以及表格/画布内部滚动是否仍可用。已有 `tests/*browser*qa.cjs`、`tests/moodboard_browser_qa.cjs`、`tests/canvas_interaction_qa.cjs` 和相应 Python runner 可作为浏览器回归候选；新增场景要沿用这些测试的隔离数据方式，勿连接真实运行数据。本文只是统一规则，不宣称本轮已执行浏览器验收。
