### 1.1 最新用户已确认要求：覆盖旧文档的专节

本节供主线程总 Markdown 的优先级索引使用：**最新用户明确确认 → 本节 → 旧确认文档/Golden 行为**。以下是已确定产品要求，不能回退为待确认选项；本次不实施其数据库/服务器变更。

1. 32 列是预设全集，默认约 7 基础业务列；侧栏默认展开。预设未加入不代表不存在，永久删除后不自动重建。
2. 全项目无需提示的审阅标记时隐藏整评论提示列；有标记时其他无标记行可为空。统计 scope 是完整项目，不是当前筛选/页/视口。刷新/切视图/返回审片必须使用同一标记模型。
3. 所有可见业务列都可永久删除并清除业务内容。内部技术 IDs、revision、权限等系统结构保留、不显示；同名显示列不能因此变成不可删除，也不能把原业务值换个内部字段名继续保留。强制技术字段需要独立的中性运行默认值与迁移合同，不能保留被删业务内容的副本。隐藏只变视图，回收只软删除并保留当前值和历史快照；两者都不是 purge。
4. 永久删除 UI 明确确认列名及影响数量（活动镜头、回收镜头、历史版本/快照、暂存/导出任务等），服务端执行时再次校验范围与版本。永久删除完成后当前数据和历史 snapshots 都不保留该列业务内容；服务器内 staging/cache/exports、派生预览/索引/任务结果必须失效并清理。purge 记录仅存技术 ID、操作者、时间、影响计数、状态，不存原值、before/after 或可恢复快照。
5. 历史版本普通写入仍不可变；**永久删除是高优先级内容清除例外**。不能用 immutable 策略留下被清除的值，不能以隐藏版本 UI 代替清除。版本可保留结构和“该字段已永久删除”状态；任何 compare/restore/branch/merge/import 重放都受 purge tombstone 约束，不能复活该字段值。
6. 软删除可以通过 inverse command 撤销，永久删除不可撤销；purge 触发相关本地草稿/undo/redo/clipboard/query/派生缓存失效。UI 确认说明具体删除范围和不可撤销，属于操作合同，不添加产品免责声明。
7. 所有导出强制可追溯隐写水印，截图/裁剪后必须有真实验证证据。可见水印可关；metadata、附件、hash、QR、DM 都不能代替隐写信号。
8. 语速样例是固定 TTS 音频，可播放/停止/重播；文字计时示意不能代替试听。
9. 工程 PDF 默认 QR 多码分片，可选 DataMatrix ECC200；真正数据与附件包往返，离线重组/去重/校验/映射预览后再追加或覆盖。正文、码与附件必须使用同一个导出 allowlist。大图放附件/ZIP，不塞码；不携带 IP、密钥、session/share token。
10. 列归档功能已去掉，列生命周期只有“删除”（软删除到回收站，保留历史）和“永久删除”（明确确认，清除当前及历史内容）。不提供“归档”入口或归档状态。显隐是共享视图中的显示配置，不是第三种删除方式。新增自定义列宽、自定义行高、自动列宽、自动行高；**禁止自定义列高**。列顺序/可见性/宽度/行高策略持久化为项目共享视图并同步全部用户，按权限、revision 和异步 ack 生效；手动尺寸优先，重算入口不得静默抹掉手动配置。
11. 最新动画要求覆盖旧规范：不设计面向产品的 Reduced motion 模式或减弱动画设置；采用丰富动画、统一 motion tokens、时长和 easing，覆盖控件进出、行列布局、切视图、画布、选择、保存与进度。编辑/拖动即时响应；虚拟列表不因动画重排而失焦；输入、上传和命令不等待动画完成。性能/失焦/清理合同继续有效。
12. 本轮最新用户确认覆盖较早右键方案：行菜单统一为“上插镜头、下插镜头、复制、剪切、向下粘贴”，箭头上下；表头菜单为“前插列、后插列、复制、剪切、向后粘贴”，箭头水平。保留剪切，去掉独立复制镜头；保留系统 Ctrl/Cmd+C/X/V、原有选择/计时/删除，以及用户框定的自动列宽/隐藏/新建镜头/废纸篓入口。本轮具体列操作、四列排除、改名、保护列、工具条及证据见 [列/菜单执行文档](SHOT_COLUMNS_MENUS_2026-10-02.md)。本条覆盖早稿“移除域剪切、菜单上下双向粘贴”。多选按原镜头顺序插入，复制生成新内部ID，不复制锁、权限或审核已读；镜头域快捷键仅在已选择且焦点不在编辑器时启用，输入框保留原生文本快捷键。其他未涉及完整功能仍属待实施。

工程运维说明：已下载、离线或第三方持有的文件不会因服务器 purge 自动消失；既有备份须定义保留/清除和恢复后 purge replay 边界，防止恢复数据复活。这个限制只记录在工程实施/运维方案，不进入产品免责声明。执行清除前须有不含业务值的 purge ledger 和受控恢复流程；任何备份副本均不能被标作已即时清除。

## 3. 全站动作、缓存、保存与错误合同

### 3.1 一次动作的完整路径

读取权限/实体版本→创建本地草稿或可回滚预览→明确 pending→发送标准 command→服务端权限/类型/expected revision/业务校验→单事务变更与 audit→提交成功后返回 authoritative 实体/新 revision→更新 query cache→显示已保存。重复触发通过 command ID/idempotency 或任务去重处理；不对未知结果的写请求盲重试。

服务器数据由 TanStack Query 持有，工作区导航/选择/Inspector targets 由一个 Zustand owner 持有，输入草稿留在编辑器。禁止复制一份长期实体进多个 store。选择和正在查看的镜头不同；业务 mutation 不走 Presence 通道绕过命令服务。

| 状态 | 控件与用户可见反馈 | 保存/恢复合同 |
| --- | --- | --- |
| 初次读取 | 保留 Shell；当前区域骨架/“正在载入…”（M5） | 无数据不呈假值；错误有重试入口 |
| 缓存后台刷新 | 旧数据继续可读，局部刷新指示 | dirty 草稿不被 refetch 覆盖；账号切换清缓存 |
| dirty | 当前字段/行标识“未保存” | Blur/切换等按模块触发保存，Esc 取消当前输入；IME composition 不提前提交 |
| saving | 当前动作 spinner、按钮固定宽度，相关重复操作禁用 | 其他不冲突的工作可继续；禁止将 dispatch 当作成功 |
| acknowledged | 保存勾选/“已保存”，M1/M5 | 使用返回版本刷新缓存，无变更不生成假 revision/audit |
| failed | 字段旁可操作错误、重试、复制错误 | 输入/上传文件引用/导出配置/任务选择保留，适用预览回滚 |
| conflict | “此内容已被更新”，查看最新、比较、保留我的草稿后重试 | 409 不自动覆盖，重试基于新版本重新确认范围 |
| 401/403 | 重新登录或返回可访问入口 | 不循环提交；秘密字段不进入复制错误；草稿保留在原用户隔离域 |
| 长任务 | 独立进度、取消/重试、后台继续、可返回列表 | 导入解析/OCR/渲染/导出/TTS 不冻结整个站点；明确任务取消是否已提交 |

乐观反馈用于选择、列显隐/宽度、拖动预览、可逆字段预览和本地附件进度；数据删除、覆盖导入、权限变更、永久删除和导出交付以服务器确认后完成。pending 行/资产有临时状态标志，不能进入正式导出或统计。

当前 `Providers.tsx` 的 QueryClient 有 `staleTime:5000`、`retry:1`、账号变化 clear；`useProduction.ts` 的 Shot PATCH 成功更新缓存、settled invalidate，创建后插入真实返回实体；Inspector 已有草稿/409 处理。大厅仍是独立 useState/fetch，设置页仍 alert/confirm，很多读页面没有一致的 background refresh/失败反馈。因此“全站 async/cache/optimistic/draft-retain”是待收敛合同，不是当前全部满足。

### 3.2 可操作错误与“复制错误”

统一错误 UI 显示：发生了什么、受影响对象、下一步动作、短错误编号。示例产品文案：“这条镜头未保存。你的输入已保留。重试 / 查看最新 / 复制错误”。不要把 SQL、Python traceback、HTML 代理错误、请求头或响应原文直接展示。

复制错误生成受控对象：`errorId/time/module/action/safeCode/httpStatus/requestId/appVersion`，可加用户明确可见的镜号和 sanitized 参数摘要；排除 token、Authorization、Cookie、账号密码、IP、服务器路径、完整请求/响应 body、TTS 原文及真实素材内容。错误诊断明细由后端安全日志处理，不能通过复制入口泄漏。

当前 `apps/web/lib/api-client.ts` 的 `ApiError` 解析 `detail/error/message`，也能把任意 text response 放入 Error.message；多处页面再直接展示 message。这是可核实缺口。补统一 safe error normalizer、服务端错误 envelope 和局部反馈 pattern，再迁移全站 consumer；复制按钮成功/失败都有 M1 反馈，失败支持选择并手动复制已脱敏文本。

### 3.3 Undo / Redo（标准命令的 inverse）

入口：工作区项目操作区 `撤销`、`重做`；快捷键 Ctrl/Cmd+Z、Ctrl+Shift+Z/Cmd+Shift+Z（Windows 可兼容 Ctrl+Y）。文本输入有原生 undo 时不截获。按钮显示待撤销动作短名称，不展示内部 command 实现。

历史项记录 commandId、actor、project、受影响稳定 ID、before/after、expected revisions、inverse command、资源引用、是否可撤销。先执行普通命令且获服务端确认后进 undo 栈；撤销发送 inverse 命令，依然走权限/revision/audit/事务，成功才移动栈；redo 重新执行 forward command，成功才移动。新动作清空 redo；409 保留历史项并进入比较流程，不能把其他用户的新值静默改回。

适用：编辑、创建/软删除恢复、排序、列配置/回收、素材关联、画板对象增删/移动、批注可逆操作。字段永久删除/行 purge/已经下载的交付文件不伪装可恢复；对应动作明确作为历史边界。系统剪贴板复制不写业务，粘贴新增形成一条创建命令，可通过inverse软删除新镜头；没有域剪切命令。批量操作是一条可逆命令，不拆成半成功列表。M0/M1/M5；当前 canonical 尚无贯穿模块的 command/inverse history owner，旧画板/Legacy undo 只能作行为证据。

## 6. 项目共享视图、列宽与行高

### 6.1 控件和同一权威 owner

表格工具条“尺寸”提供自定义列宽、自动列宽、自定义行高、自动行高、重新计算自动尺寸。列标题菜单对当前列提供“设置列宽/自动列宽”，行尺寸入口对当前行或所选行提供“设置行高/自动行高”。镜头菜单遵守最新Ctrl/Cmd+C/V与向上/向下粘贴规则；尺寸动作放独立分组，不复活duplicate或域剪切。

表头边界拖动列宽，行下边界拖动行高；拖动实时显示 px，释放提交一次，Esc 恢复拖动前值且不写库。数值输入使用共享 Input，标注 px、允许范围和“应用”；键盘同样可完成。**不提供自定义列高**，表头高度由一致布局规则决定。手动配置显示“手动”，切回自动须明确选择，输入内容变化不覆盖手动值。

持久配置属于项目共享 Saved View：`viewId/productionId/configVersion/revision/columnOrder/visibility/columnSizing/rowSizing`。列 sizing 保存模式、manualPx/effectivePx/min/max；行 sizing 保存全表策略、按稳定 Shot ID 的覆盖、自动计算版本/结果。配置先正规化再保存；未知/已 purge 的 field key 拒绝或剔除，不能 resurrect。排序不会把某镜头行高转移给另一镜头。

共享视图内顺序、可见性、列宽、行高策略修改同步全部用户。用户个人搜索、临时选择、滚动位置及播放头仍为个人 UI 状态；不能因某用户筛选产生全项目尺寸回写。现有命名保存视图可继续保留，但项目默认共享配置为真实启动来源，不以 localStorage 作为权威。

### 6.2 自动尺寸算法

| 计算 | 输入、规则和建议初值（实施时在桌面校准） | 手动优先与重算 |
| --- | --- | --- |
| 自动列宽 | 完整 active 镜头测量范围+可见字段+稳定格式化器；在 Satoshi/Sarasa 字体 ready 后，量表头/排序图标、实际显示文字、控件、padding。镜号/TC 按最长格式字符串；图像按缩略图布局；长文本按文本可读上限，不无限增宽。建议业务列 min 80/max 480px，镜号/勾选等按专用 token | 每列 manual 优先；“自动列宽”明确移除目标手动覆盖；“重新计算”仅更新 auto 列 |
| 自动行高 | 先得到有效列宽，再测每行可见单元格的换行/行高/padding、图片和控件；取各单元格所需最大高度。建议最小 48px、auto 内容上限 240px，长内容提供展开/Inspector | row override 优先于全表 manual，manual 优先于 auto；“自动行高”明确移除范围覆盖。被隐藏列不撑行高，列宽/字体/内容变化使相关 auto 结果失效 |
| 大工程测量 | 以项目固定内容 revision 与字体/格式化版本，分批 worker/离屏测量；进度与取消；一次计算保存统一结果，禁止每个浏览器收到同步后再分别回写 | 明确“重新计算：全部自动列/行或指定范围”；本次计算结束前内容有变则标记过期，不覆盖较新配置 |

字体、locale 和格式化差异可能改变测量，权威计算使用共享配置明确的字体/格式化版本；其他用户先应用已保存 effective 尺寸。量不到未加载数据时先取完整 read model，不用当前 DOM 可视行充当全集。显示上限造成的内容折叠必须有读全文入口，不拉伸图片也不默默丢字。

### 6.3 权限、revision、同步和失败

客户端发送 view ID、expected revision 和 patch，服务器校验 project scope 与 `view.write`（建议新增细分权限；现有为 shot.write），正规化配置→加锁/revision compare→变更/audit→commit→返回正式配置。drag preview 为本地乐观状态，ack 后才“已保存”并通知其他用户更新；实时事件携带 viewId/revision/changedKeys，迟到事件忽略，断线重连 GET 最新。

403 保留输入并显示无共享编辑权限；409 保留本地 patch，获取服务器配置，对冲突项展示比较，非重叠项可正规化后重试，不能发送整份旧配置盖掉别人。断网保留 pending 值/重试；no-op 不升 revision。表格字段软删除/永久删除事务同步清理所有共享视图引用；旧 localStorage/保存视图/导出配置再次加载时过滤 tombstone。删除的行 ID 不参与尺寸结果。

源码事实：`SavedViewService` 已有 `is_shared`、角色 shot.write 检查、`with_for_update`、revision 409、no-op、audit、`sanitize_saved_view_config/purged_column_keys`；`ShotSavedViews.tsx` 能 create shared view、overwrite 带 revision、apply config。`ShotColumnManager` 已有行高 Select 的 `auto` 选项，真实内容自适应测量/持久结果需另验。现有支持不等于自动向全体用户同步默认视图；必须扩展现有 SavedView owner，`config` 仍通用字典，需要类型化尺寸合同、按字段 patch 的冲突处理、全体更新通知与统一启动消费，不能重建第二个保存视图系统。M0/M1/M3/M4/M5，auto 应用布局过渡120ms；不产生每帧网络 mutation。

## 7. 行、列管理、筛选与上下文菜单

列管理采用工具条 Popover：搜索 + “当前列 / 可添加预设 / 自定义 / 回收站”四区；当前列支持改名、类型（预览转换影响）、显隐、顺序、宽度、删除。所有业务列可永久删除，基础列也不例外；数据库内部字段不混入此目录。新增自定义列提供名称/类型/默认值/选项/校验，保存成功才加入共享视图。回收站支持恢复和永久删除，无归档页签。删除不清历史；永久删除先显示列及影响数量，确认与服务端重新校验后清除当前/历史/缓存。失败保持可恢复状态及清除进度，不能显示已完成。

## 9. 素材、图片裁剪与情绪板

素材库保留媒体优先网格，支持类型/未使用过滤、搜索、原名/尺寸/大小/引用、预览和批量上传。上传先本地预览与进度，后台校验/生成缩略图；失败保留临时卡与重试，取消终止作业并收回孤立资源。原图不被缩略图覆盖；引用删除先显示影响，并按实际权限执行。

## 10. 2D/3D 灯光与自动旁白计时

灯光保留左器材库、中画布、右场景对象/画板设置/分镜关联；2D、分屏、3D 三模式以及俯视/鸟瞰/漫游/3⁄4、选择/平移/移动/旋转/环绕/吸附/光束。器材参数、坐标单位/旋转/尺度属于一个对象数据源，两个renderer同步消费。场景选中、对象锁和画布锁明确区分；undo inverse按对象命令统一。器材型号标签不是性能仿真认证，产品标注不写免责声明。离开页面释放RAF/GPU/listener，保存不依赖renderer退出动画。

估时先分词/停顿，再使用所选voice/rate实际音频时长校准；预计与TTS实测区分。按镜头或批量自动计时先显示帧数变更预览，锁时长项保留；最大余数分配确保帧总数一致，TC不由页面自行拼接。缓存key包含文本digest、语言、voice、provider/model/词典版本、rate和项目权限域；purge清关联音频。默认本地TTS，配置外部provider后按数据处理范围使用。M7/M5用于滑杆/播放/生成进度。

可见水印管理文本/图片、位置、大小、透明度、旋转、重复、启用/删除，预览立刻呈现。不可见水印强制包含匿名traceId、exportId、载体/算法版本与受控校验；真实身份映射留受控服务。PDF正文图像、导出图片及Word渲染内容需实际隐写编码/解码；文本工程交换增加隐写文本载体/受控嵌入媒体，同时保留签名追溯。没有合格载体不能把hash/metadata称为隐写完成。

首轮水印实验矩阵：原图/导出页、裁剪保留75%/50%/25%、桌面截图原尺寸/重采样、JPEG90/70/50、缩放0.5/0.75/1.5、打印照片；记录识别率、位错误率、误报率、视觉质量和算法版本。候选需服务端解码并验证trace签名，错误不能归属到真实用户。目标先验证原样100%、主要截图/50%裁剪场景≥95%正确识别，样本≥100/场景并单列置信区间；这些是准入目标，当前无实测，不能宣称抗任意裁剪/截图。码区留白不被水印破坏。

## 12. 协作、管理员用户管理与全站同步

编辑前字段锁：project/entity/field维度、TTL租约、owner/颜色；获锁后编辑，失锁保留草稿但不继续提交。release、断线过期、冲突和管理员解锁有明确状态。指针/表单框高亮按自动分配用户色，显示名称与非颜色标识；Figma样式光标、跟随选区边框、多人presence名单。临时pointer/heartbeat只在Redis，不能每帧写业务数据库；持久编辑和共享视图经revision事务回执后广播。

首页管理员入口“用户管理”：用户/组列表、搜索、创建或邀请、启用状态、组分配、颜色、角色/能力配置。后端限制管理员，不以隐藏菜单代替权限；普通用户不可借URL访问。颜色选取自动避免活跃协作者撞色，用户可在允许配置范围更改；组角色与项目成员权限优先级明示，权限变化使缓存/链接授权失效。不把管理员入口混进项目封面卡。

全站异步：适用动作先更新本地draft/预览，再上传/提交；同步状态区分本地未保存、上传中、服务器已保存、冲突、失败。更新时间与操作者由服务器ack产生，刷新提供“已刷新/发现新版本/草稿仍未保存”，不通过刷新丢输入。Query缓存带权限域和revision，出组/退出/purge清缓存；缓存媒体按版本，旧响应不覆盖新目标。
