## 1. 重新审计的结论和边界

当前工程已有真实 shadcn/Radix 组件基础，但尚未形成完整、统一、功能对等的产品界面。`packages/ui/components.json` 明确为 `new-york / neutral / lucide`，根组件已有 Button、Input、Card、Checkbox、Dialog、Popover、DropdownMenu 等；业务页面仍存在过度缩小控件、浏览器原生 alert/confirm、状态占位、功能缺口和布局偏离。

本轮读取了根与 Legacy AGENTS、组件总规范、视觉基线、产品/页面/控件/owner 矩阵、工作簿、路由与组件清单、关键页面和根控件源码；核对 Golden Baseline 的 `static/index.html`、`shot_versions.py` 及当前 master 增量，并重新查看三张留存截图。**这是代码与文档复核、历史截图复核，不是最新运行版本的全量浏览器或后端验收，也没有逐行读完全部仓库。**

## 3. 桌面信息架构与页面方案

### 3.1 统一工作区骨架

沿用既定 TopBar 50px；左导航展开 224px、收起 64px；详情目标 380px；Project Hub 内容上限 1152px。导航项高 36px。正文建议 14px/20px，辅助信息 12px/18px，页面标题 20px/28px；表格文字不通过普遍缩成 10px 来容纳更多列。字体沿用 Satoshi + 更纱黑体，时码/镜号使用等宽与 tabular numbers。

空间节奏为 4/8/12/16/24/32px，页面内边距 16–32px。Card 继承根 shadcn geometry；表格、Inspector 不套多层 Card。图标常用 16–18px；纯图标交互必须有名称和 Tooltip，不能只靠 hover 才出现关键操作。

```text
┌ TopBar 50：品牌 / 当前工程                     真实状态 / 主题 / 账号 ┐
├ Nav 224/64 ┬ Feature：标题、上下文、一个主操作                       ┤
│            ├ 查询与工具（必要时两行，不用压缩按钮掩盖超宽）           │
│            ├ 主工作面（自己滚动）                ┬ Inspector 380   │
│            │ 表格 / 媒体 / 时间线 / 画布          │ 仅显式打开       │
└────────────┴────────────────────────────────────┴─────────────────┘
```

这是布局提案；各页采用适合业务的区域，不要求全部显示 Inspector。1440 宽且 Inspector 打开时，表格可水平滚动；TopBar 和主操作必须完整可达。

### 3.2 Shot Table

- 第一行：页面标题/当前视图与计数；右侧主按钮“新建镜头”。第二行：搜索、筛选/分组、保存视图、列管理和更多。自定义字段是字段配置入口，避免与列显隐同名。
- 固定选择/镜号区域；其余列有明确水平滚动范围。表头与行共用列宽模型和滚动 owner。长文本允许换行偏好/行内展开，不能仅靠截断与 Tooltip 承载核心内容。
- 单击选择；可编辑单元格双击进入编辑，停止向行双击冒泡；非编辑区域双击或详情按钮打开 Inspector。Shift 范围与 Ctrl/Cmd 多选依据当前呈现顺序。
- 多选时在既定工具区域显示数量、批量动作和取消选择，避免再悬浮一条遮住第一行的工具栏。
- 拖柄发起排序；筛选/分组/非默认排序下遵循完整顺序合同，明确说明为何不能拖动；不能提交当前局部列表冒充全量顺序。
- 行/列右键动作逐项对照旧版；键盘 Shift+F10 同等可达。新建/插入/复制/清空/删除等只有真实命令完成才能标完成。

### 3.3 Inspector

顶部为镜号、名称、关闭；主体依次为媒体/图框、描述、旁白、技术属性、自定义属性与相关状态。分段标题+Separator；信息默认阅读，编辑控件只在必要位置出现。保存状态始终可见但不盖住字段。

选择和 inspected target 独立；切镜头、关闭、返回 Hub、切项目都要处理 dirty draft。409 在字段附近提供本地/远端差异、保留输入、重新应用的明确入口；不能强制刷新清除输入。拖动尺寸若非既有能力先不新增，先验收固定 380px。

### 3.4 Review

以“当前镜头的媒体和修改”为中心。提案：内容区域内镜头队列 200–240px，评论侧栏约 320px，中间自适应；不足时先折叠镜头队列，不把全部工作区变成纵向大卡片。

中间顶部为镜头身份与明确的版本选择；媒体按实际比例显示，缺媒体用紧凑 Empty，不留一个巨大黑色占位。下方为 Before/After 或行内差异；右侧评论、回复、引用与编辑器同时可达。历史/版本列表在辅助区域按需展开。底层快照、版本恢复、分支、合并保留真实命令与确认。

每条可处理差异显示字段、旧值、新值、作者/时间及接受/拒绝动作；如果当前 API 只支持整个版本 accept，先标合同缺口，禁止前端假装逐字段操作。旧 Ready for Review/Approved 等保留历史可读性，产品动作映射完成前不增加审批型按钮。

### 3.5 其余页面

- Hub：保持行式项目卡，封面→名称→规格→操作顺序；真实空态引导创建；大量项目验证长名称、缺图和菜单，不用空旷页判断质量。
- 卡片/墙：媒体→镜号→描述→元数据→已有动作；统一焦点与选择，真实图片加载保留画幅空间。
- Timeline：尺、轨道、播放头和缩放是主要信息；时码来自共享 timecode 包；拖动后服务回执与撤销不得被动效替代。
- Assets：缩略图/文件名/类型/状态统一；媒体失败给重试和原因；预览与修改权限分开。
- Narration：逐镜头文本与计时成组，预览后才应用；总时长和锁定可见，不改变未选镜头。
- Canvas：工具和 Inspector 采用 shadcn；2D/3D 绘制、坐标、命中、RAF 与资源释放由领域渲染器负责。shadcn 不提供分镜画布引擎。
- Import：每步可回退且保留映射；错误定位行列，提交摘要列出模式与影响范围；提交失败保留预览。
- Export：用真实版式缩略图表达表格、九宫格、单镜头、横向版；字段选择、页设置、进度、下载失败可见。工程附件/二维码与普通打印分开说明。
- Settings/Trash：字段按业务分段；危险动作明确作用对象、能否恢复与影响；不可混称归档、删除、永久删除。

## 4. 控件规范与实现批次

| 控件组 | 统一规则 | 本轮后续工作 |
| --- | --- | --- |
| Button/IconButton | 根 variant；default 40px、sm 36px、lg 44px、icon 40px；主/次/危险分层；loading 不改变宽度 | 清点页面 h-6/h-7/h-8 覆盖；仅明确表格 utility 可例外 |
| Input/Textarea/Field | 40px 单行输入；有 label、说明、错误；多行 Enter 换行 | IME composition 不触发保存；沿用 Ctrl/Cmd+Enter；草稿失败不丢 |
| Select/Combobox | 固定枚举 Select，真正大列表才用可搜索组合控件 | 场次用真实名称/编号，空数据与加载有状态；不伪造选项 |
| Checkbox/Switch | 多选与全选中间态清楚；Switch 只用于即时生效布尔属性 | 动作失败恢复/说明；不可拿 Switch 当提交按钮 |
| Table | Renderer 与 temporary editor 分开，sticky/scroll 单一 owner | 根 Table 外观+现有业务模型；不为采用 Data Table 示例重写全部排序状态 |
| Dialog/AlertDialog | 创建/配置用 Dialog，破坏确认用 AlertDialog；焦点返回与描述完整 | 移除页面 alert/confirm；长内容 body 滚动，footer 可达 |
| Popover/Dropdown/ContextMenu | 12px 建议碰撞边距；Escape、外点、键盘入口、焦点恢复 | 真右键需要 ContextMenu 行为；若保留 Dropdown 适配必须证明坐标/焦点对等 |
| Tooltip/Badge/Separator | Tooltip 辅助解释，Badge 用文字表达状态，不仅靠颜色 | 统一语义；制作方式不铺满高饱和色 |
| Skeleton/Empty/Alert/Progress/Toast | 加载、空、失败、缺权限、离线分开；进度来自真实任务 | 根包按真实消费者补齐；错误留页面，Toast 不能是唯一错误载体 |
| Tabs/Accordion/ScrollArea | 只用于已有业务内容组织 | 不恢复旧顶层 View Switch；不制造嵌套双滚动 |

新增根控件时记录官方来源、采用版本/提交、本地差异、真实消费者与键盘验证。组件库调试页只作开发验收工具，不作为新增产品页面。[官方组件目录](https://ui.shadcn.com/docs/components)

### 全状态合同

每个可交互控件至少定义 default / hover / focus-visible / pressed / disabled；可保存控件另有 dirty / saving / acknowledged / failed / conflict。Selected、Active、Focus、Editing 必须独立。只在服务器确认后显示已保存；错误不能仅变红，需文字与恢复入口。

根 primitive 不访问 API、不持有项目状态。领域控件负责 Shot 等语义，feature 负责请求与权限。服务数据在 query 层，工作区 UI 在单一 store，表单草稿在本地；不增加另一套并行状态 owner。

## 5. 动画和动态图标详细合同

以下是统一目标值，实施时落在根 motion token 中；当前已有 fast=120ms、normal=180ms、standard easing，其他为计划补齐。标准曲线 `cubic-bezier(0.2,0,0,1)`；退出可用 ease-in，避免反弹。CSS 控件动效优先绑定 Radix `data-state`；只有确需布局编排才引入受控 motion wrapper，不同时维护 CSS 和 JS 两份可见状态。[Radix 动画生命周期](https://www.radix-ui.com/primitives/docs/guides/animation)

| 场景 | 动作 / 时长 | 退出、打断与降级 |
| --- | --- | --- |
| 按钮 hover/active | 色彩/边框 120ms；无整块放大、上浮 | 键盘 ring 立即出现；disabled 不运行 |
| Checkbox/开关 | 勾选淡入或拇指位置 120–160ms | checked 立即更新，失败按真实状态恢复 |
| 折叠箭头 | 同一 chevron 0→90°，160ms | 快速反向从当前位置继续 |
| Tooltip | hover 延迟约 400ms、出现 120ms，位移≤2px | 键盘焦点可读；关闭 80ms；不遮主操作 |
| Popover/菜单 | opacity + 2–4px，140ms | 退出 100ms；开合中 Escape 有效；完成后无透明命中层 |
| Dialog | 遮罩淡入 180ms；内容 opacity + 4px、scale .99→1，200ms | 退出 140ms；维持 focus trap 与正确 focus return |
| Inspector | 主区与详情同步展开 220ms | 动效不重挂编辑器；快速关开保留草稿；布局测量只一个 owner |
| 左导航 | width 180ms，文字淡出≤120ms | 图标位置不漂移；collapsed 标签由 Tooltip 提供 |
| 路由内容 | 可选 opacity 120ms | 不对整个 App blur；不因路由淡入延迟真实输入可用时间 |
| 拖拽排序 | 拖起轻微阴影，2px 插入线；落位≤160ms | 键盘等价；交互命中用真实几何；失败恢复服务器顺序 |
| 媒体加载 | 保留画幅；真实加载后 crossfade 120ms | 不无限闪烁缺图；失败终止加载动画 |
| Saving/Sync | 专用 spinner 在 pending 时循环；成功 check crossfade 120ms | 仅回执后成功；错误切 alert + 持续文字；不旋转保存图标 |
| Toast | opacity + 4px，160ms，关闭120ms | 不挡导航/输入；可操作通知键盘可达；错误仍有页内副本 |
| 画布操作 | 指针跟随与播放头由实时绘制驱动 | 不给坐标/拖动套 CSS easing，避免迟滞；卸载取消 RAF/listener |

`prefers-reduced-motion` 下移除位移、缩放、旋转和布局插值，必要淡入≤80ms或直接切换；加载用静态符号+文字。若动画 CSS 使用独立 duration，必须明确覆盖，不能只将两个 token 置零就声称全部支持。

Lucide 为通用图标，领域器材可用统一 Domain SVG；尺寸16/18/20/24px、stroke约1.75–2。保存、同步、展开、播放状态是动态的；普通搜索/设置/删除图标保持静态。错误不震动，空闲不旋转，不引入装饰性持续动画。

退出动效不负责保存和状态机；避免依赖 animationend 完成业务。操作中断、快速重复开合、组件卸载、窗口失焦和 reduced-motion 切换都必须保持同一业务结果。

## 6. 实施路线、依赖与交付件

按阶段门槛排程，不给缺少合同核验的复杂模块承诺虚假天数。每阶段拆成一个模块/一组独占文件的小提交并立即推送。顺序为 P0→P1→P2→P3→P4；随后 P5/P6 可按独占文件并行，P7 收尾。

| 阶段 | 具体切片 | 主要 owner | 完成门槛 |
| --- | --- | --- | --- |
| P0 基线冻结 | 同步当前 master；动作台账；Review 语义冲突；旧资料事实校正；同数据前后截图清单 | docs + coordinator | 每项有来源/去向/状态，新增设计与已移除概念分开 |
| P1 根控件 | 补反馈/确认/菜单所需 primitives；tokens、z-index、字体、图标、motion、states | packages/ui | 控件真实消费者和键盘/动画闭环；无业务 API 混入 |
| P2 Shell/Hub | TopBar/NavRail；项目行/封面/菜单；登录与身份；新建工程 | app-shell + productions/auth | 1440 桌面浅深色、空/多项目、长文案、切项目/退出通过 |
| P3 Shots/Inspector | 新建合同修正→工具栏→表格→列/字段/视图→菜单/批量→Inspector/草稿→undo 缺口 | shot components + shots + corresponding services | 所有保留动作有消费者；长文本/横滚/选择/409/表单可用 |
| P4 Review | 媒体/差异/评论布局→版本选择→回复引用/解决→逐条审计合同→恢复/分支/合并 | review page/hooks + Review/Version services | 首屏可审阅和评论，版本/差异动作语义明确；无审批系统回潮 |
| P5 次级生产页 | 卡片/墙、Timeline、Assets、Narration；各自真实保存与错误 | feature 独占文件 | 各页动作台账闭合、刷新持久化与状态一致 |
| P6 工程流程与画布 | Import/Export/PDF/Word/Share/Settings/Trash；Board/Lighting API 后接 Canvas Chrome | 文档/PDF与画布分队，服务接口先收敛 | 无损合同可证明；特殊格式/设备字段不丢；实际权限有效 |
| P7 收敛与退役 | 旧消费者/事件/CSS/构建引用清点；移除竞争 owner；端到端桌面验收 | coordinator + owner 各自清理 | 零消费者证据、回滚路径、无遗留假入口，状态有真实证据 |
| P8 后续适配 | 在桌面核心通过后另排 1024/768/375/320 与触屏 | 独立后续批次 | 本轮不测试窄屏，不把它当桌面完成的前置要求 |

P3 的批量、undo、字段写入等依赖 canonical ShotService；P4 逐条 diff 依赖明确的 patch/revision/audit；P6 Canvas 依赖 Board 数据合同；PDF 往返依赖附件/哈希/QR；Presence 依赖认证实时通道和临时状态后端。后端未就绪时标 blocked，不用 UI 演示替代。

### 每个小切片的操作顺序

1. 给出功能基线证据、当前代码位置、期望入口与状态、UI 草图或控件组合。
2. 实现单一 owner 的垂直切片；保留 API/权限/冲突/草稿；列出删除候选但不盲删。
3. 按用户小段上传要求可先推送，注明尚未运行的检查；上传不代表验收通过。
4. 在 1440 桌面验收真实界面、菜单、输入、保存与失败；影响后端合同时进行对应隔离验收，只有真实结果才能填 PASS。
5. 保存前后截图/manifest，更新同一条动作台账，保留问题与下一步；门槛通过才退役旧 owner。

## 7. 验收矩阵与证据

桌面第一标准为 1440×900、100% 缩放、浅/深主题；历史 1440×1000 图片保留原样，不伪标尺寸。需要时补大桌面，但本轮不测窄屏。先完成 Shell/Hub、Shots、Inspector、Review，之后扩展其余桌面模块。

| 维度 | 最小必查 |
| --- | --- |
| 视觉 | 关键按钮完整、文本可读、主次明确、无永久输入格子、无无意义大占位；真实图/无图/错误/长名称 |
| 交互 | 创建、选择、多选、双击、行内编辑、列管理、右键、滚动、拖动与键盘替代、关闭/返回 |
| 表单 | 必填、禁用、IME、多行输入、重复提交、异步加载、打开两次、失败保留、跨镜头草稿 |
| 动画 | 快速开合、退出命中层、focus return、低动效、pending→success/error；无 layout jump |
| 数据 | 创建/修改后刷新保留；409、不变更 no-op、权限、批量原子性、删除恢复、导入导出往返 |
| 场景 | 零数据、单条、多条长文本、自定义字段、图片混合、会话失效、请求失败、慢响应 |

截图新文件放 `docs/audits/visual-evidence/YYYY-MM-DD/<slice>/`，不覆盖旧图；manifest 记录 commit、route 模板（避免私人参数）、viewport、image dimensions、theme、合成数据说明、动作、期望/实际、状态。历史 outputs/screenshots 与 audits/screenshots 目录保留引用，不移动删除。截图不能证明所有后端合同。

完成状态分别记录：代码已接入、视觉、交互、后端合同、迁移/退役。任一需要的门槛未完成，不能总写“完成”。本次计划文档交付不提升任何模块状态。

## 8. 动作台账模板和协作约束

每条填写：`ID | 模块/动作 | Golden 来源/后续决定 | 当前 consumer | 目标 UI/控件 | API/service | 权限/状态/错误 | 实施 SHA | 图像证据 | 验收结果 | 旧 owner 删除证据`。

示例首批任务：

- SHOT-01：新建入口、真实场次、编号策略、重复打开、失败恢复；先修当前恢复切片的不足。
- TABLE-01：主/次工具区域、列宽、长文案、横滚；保留已接通的列/视图/字段。
- INSPECT-01：380px、显式打开、选择独立、切镜头草稿与409。
- REVIEW-01：媒体/差异/评论同屏，回复/引用代码复用；逐条审计与旧审批状态明确区分。
- MOTION-01：根 Dialog/Popover/Menu 的 open/close、焦点返回与 reduced-motion。
- SETTINGS-01：生命周期文案对照服务，替换 alert/confirm，真实错误可恢复。

共享包由一个 owner 修改，业务执行者只消费约定 API；同一页面只分配一名实施者。Luna 用于目录/文档/控件迁移等边界清晰任务；复杂状态与合同由主协调审查，默认不使用 Astra。每次接手读取当前 SHA/diff，不覆盖其他会话工作，不把此计划当作已发送的子任务。

已有最新 master 增量（身份恢复、账户缓存、导入服务、设置草稿等）是新重设计的输入，必须保留。新 UI 的验收依据是功能覆盖、统一组件及实际体验，而不是“页面引用了 @frameforge/ui”。
