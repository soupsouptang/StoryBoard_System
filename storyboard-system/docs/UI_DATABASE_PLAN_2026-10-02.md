## 需求 8：批注提示

现有 `User` 无用户颜色字段；批注记录有作者、时间、解决状态，但无逐用户已读水位。全局 `is_resolved` 不能替代当前用户已读，前端本地隐藏也不能保证多人、多设备一致。

建议最小变更：

1. 用户增加可空 `annotation_color`（规范化 #RRGGBB，分配默认色；自定义入口沿用现有用户设置权限）。批注列表/摘要关联最新批注作者颜色。
2. 增加 `shot_comment_read_states`，唯一键 `(user_id, shot_id)`，记录已读时间/水位。外键级联、必要索引；用户只能写自己的水位。
3. 摘要 API 一次返回项目内各镜头当前用户未读/未处理数量及最新作者颜色，避免逐行请求。
4. 进入对应审片镜头并成功呈现批注后，用服务器确认的水位标记已读；新批注晚于该水位时重新提示。全局解决状态沿用现有服务。
5. 计数真实值由服务器计算，UI 上限 99；旧数据初始已读策略在数据库方案确认时确定。新增批注、回复、解决和跨用户权限均纳入事务/审计与隔离数据库测试。

先完成 UI 列占位、路由及展示组件；没有真实接口前不宣称已读或多设备功能完成，不伪造持久化。

## 需求 11：32 列的语义与持久化

页面按确认顺序和名称展示。既有 Shot 字段直接复用；`镜头/镜号`、`运镜/机位运镜`、`画面描述/原描述` 等不自行合并语义。

需要数据库阶段逐项确认：`内外景/日夜/场景地点` 的 Scene 与 Shot 归属；`对白角色/剪辑转场/原镜号/可行性/建议替换内容/原描述/执行方式` 的已有映射与新增字段；导入原始值保存、类型、空值、必填规则、导出映射、兼容与回滚。优先复用现有自定义字段，未经确认不自动创建或将展示字段写入错误属性。

迁移前给出字段映射表、DDL/迁移、旧数据填充、API 类型、兼容与回滚计划，再取得用户确认。UI 修改结束后提醒用户一起解决以上两项。
