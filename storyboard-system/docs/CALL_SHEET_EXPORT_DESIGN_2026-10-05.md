# FrameForge 通告与制作导出设计

日期：2026-10-05。状态：需求规划；模板、发布和渠道能力不能凭本文存在认定已实现。本轮不改现有 UI、代码或部署。

依据：[扩展性总纲](VNEXT_MAX_EXTENSIBILITY_REQUIREMENTS.md)、[界面规划](VNEXT_UI_PLANNING_2026-10-05.md)、[岗位工作流](ROLE_WORKFLOW_REQUIREMENTS_2026-10-03.md)、[执行标准](EXTENSIBILITY_EXECUTION_STANDARD_2026-10-04.md)。本文件负责用户操作、模板内容、排版和验收，不创建第二套排期、人员或交付数据。

## 1. 从排期到通告的动作

通告草稿从当前排期方案、拍摄日、场景／镜头、人员、地点及准备事实查询；缺项有明确提示，不能为了填满模板猜集合时间、天气、交通或联系人。正式发布固定来源修订、允许字段、接收范围和个人集合时间，正文成为不可变发布修订。

流程：选拍摄日 → 生成草稿 → 检查来源与缺项 → 查看纸张／个人预览 → 明确发布新修订 → 按明确指令分发 → 查看送达、阅读、确认和到场。上传前已拉取总纲 3.3 的 D-36：自动联动只能更新草稿、差异和重新确认范围，不能自动发布或发送；发布与发送是两个明确动作，允许发布后不发送。

| 操作 | 可以一键做什么 | 必须保持的边界 |
| --- | --- | --- |
| 生成今日通告草稿 | 沿用最近模板，填当前授权事实 | 不发布、不发送、不把未知改成默认值 |
| 更新草稿 | 重建未人工覆盖的投影并列出差异 | 人工补充注明来源，源事实变化不静默丢弃编辑 |
| 导出已保存模板 | 固定查询范围、字段、构图和修订后异步渲染 | 不是正式交付或通告发布 |
| 发布通告 | 预览后由有权者提交固定修订 | 来源已变化则要求刷新检查，不能悄悄发布旧来源 |
| 发布并分发 | 仅在渠道、授权及接收范围已就绪后一次确认启动 | 发布与各接收人发送分别记结果，发送失败不伪造已送达 |
| 重发给未送达者 | 对指定修订与指定接收人重试 | 不重复创建发布修订，也不发给新增无权接收人 |
| 个人确认 | 确认已查看指定修订 | 不是到场、开工或对未来修订的确认 |
| 撤回通告 | 撤回访问并说明后续新修订 | 历史确认保留；已下载文件不能假装远程删除 |

“一键发布并分发”是未来可用组合，不代表本次获准真实发送消息。渠道没有接入时显示“渠道未配置”，提供授权下载／复制链接，不显示送达成功。通知方式、外部人员接入和自动发送规则需要独立确认及实施验收。

## 2. 编辑工作页

左侧为模板和区块目录，中间为纸张预览，右侧为来源、字段和接收投影检查。切换个人预览只切读取视角，不改项目权限。大步骤用完整工作页，已有交付导出入口负责入口导航，不再复制一套“下载中心”。

草稿中可以改模板、区块顺序、允许字段和独立准备备注；更改场景时间、演员、地点等权威事实使用“回到排期／人员／场景修改”。字段旁标明排期来源、人员来源或本通告补充，不能在通告改出另一套集合安排却不让排期知道。

补充内容不覆盖源事实，更新草稿显示保留、可重算、冲突三组。发布检查列出当前方案、摄制组、拍摄日、时区、来源修订、必需缺项、重要差异、接收范围和敏感字段。

缺项分两级：导致对象或时间无法确定的阻止正式发布；非必需资料如尚未录入的天气、停车说明允许显示待确认或按模板省略。各模板的必需字段须登记，不能用通用“所有字段必填”。允许例外的条目必须有实际规则、权限和原因，不能以“忽略全部错误”绕过检查。

## 3. 通告内容分层

| 区块 | 默认内容 | 来源与缺项处理 |
| --- | --- | --- |
| 页头 | 项目名、拍摄日序号、当地日期、摄制组、发布修订、发布时间、时区 | 项目和发布事实；总拍摄日未知时不写“共 N 天” |
| 重要时间 | 总体准备／开机／预计收工、个人集合及准备时间 | 实际人员安排；预计标明，不替代实际结束 |
| 地点 | 当日地点、集合点、进场说明、地图链接（已有时） | 地点事实与授权备注；未填显示待确认 |
| 当天安排 | 时间、类型、场景、镜头、地点、参与人员、准备、转场和休息 | 当前方案条目；保持稳定身份，不靠行号连接 |
| 演员安排 | 剧情角色、演员、妆发／服装／排练／开拍／释放时间 | 出演关系和实际安排；同名不合并 |
| 工作人员 | 工种、负责人、本人集合与准备事项 | 任职与任务；联系方式按字段授权 |
| 器材和道具 | 型号或名称、数量、所属时段、需求来源、未知项 | 时间段需求查询；不列可用库存或领用审批 |
| 现场注意 | 当前项目确实录入的进场、安全、天气或特殊准备信息 | 必须有来源和更新时间；不自动生成通用免责声明 |
| 联系信息 | 经授权的现场联络人及必要联系字段 | 个人数据最小投影；不存在的医院、服务商或电话号码不补造 |
| 变化摘要 | 与上次发布的时间、地点、安排和准备变化 | 比较两份固定修订，不与当前动态页面混比 |
| 页脚 | 修订身份、生成时间、页码、允许的可见水印和访问入口 | 发布／导出事实；打印不附调试信息 |

天气、日出日落、地图与交通服务本期没有验证接入；作为可选来源槽位，不写成已提供功能。不默认将所有部门联系人印给所有人。

## 4. 接收人、状态和修订

个人通告从发布修订中投影本人相关安排；部门或项目通告只按有权者范围输出。接收名单应固定到明确身份和投影，不以“当前全部成员”作为下载时动态扩散依据。外部人员邀请属于尚待独立设计的访问方式，不能以公开链接承载联系人清单。

反馈分别记录发布、通知尝试、渠道回执、打开查看、个人确认和到场；失败、未知和未发生都可见。渠道接受请求不等于设备送达。正式发布和实际确认使用服务器时间，手机本地时钟仅辅助显示。

时间、集合点或个人安排有重要变化时，新发布修订突出差异；旧确认仍绑定旧修订，当前界面可以显示“需阅读新修订”。哪些变化必须再次确认由项目规则明确，不以每次重新生成下载都要求确认。

撤回和被替代状态作为发布记录的生命周期事实保存，正文不改写。重新发布生成新修订并链接前版。临时访问权限撤销后，在线页和下载服务再次校验；已落地文件仍以水印和追踪标识识别来源，不承诺收回。

## 5. 纸张与屏幕版式

### 5.1 纸张模板

建议首版提供以下模板，不把“横版、竖版”混同拍摄画幅。纸张方向、项目画幅与分镜图框比例是三个独立配置。

| 模板 | 版式与重点 | 使用情境 |
| --- | --- | --- |
| 通告 A4 竖版 | 210×297mm，12mm 页边距，单列重要信息和分组表格 | 个人携带、少量场次和手机打开 PDF |
| 通告 A4 横版 | 297×210mm，12mm 页边距，宽时间安排与准备表 | 制片、现场打印及复杂日程 |
| 通告 Letter 竖版 | 215.9×279.4mm，独立排版而非缩放 A4 | 明确选择北美纸张的项目 |
| 当日计划 A3 横版 | 420×297mm，宽时间条与人员／地点摘要 | 筹备会议、现场公示；不默认暴露个人电话 |
| 个人在线通告 | 响应式单列，本人集合→地点→准备→安排→差异→确认 | 手机和链接查看；不是缩小的纸张截图 |

正文建议 9.5—11pt，标题 16—20pt，页脚 8—9pt；不为省页把正文缩到难读。大量内容自动续页；页头至少保留项目、拍摄日、时区和修订身份。表头续页重复，普通行尽量不断开；长备注可跨页但带条目身份。区块标题至少与下一行一起，不留页末孤立标题。

实际开始和预计时间明确标注，跨午夜用“次日”与完整日期；人员集合使用绝对时间，不用成片时码。缺失区块可以按模板省略，关键缺项不能隐藏后假装发布检查通过。

打印以浅色纸张和足够对比为默认，不直接截图网页深色主题。用户配色只用于小标识；灰度打印仍靠名字、标题、边框和状态文字辨认。可见水印不能盖住关键集合时间或二维码静区。

### 5.2 手机通告

首屏显示本人集合时间、地点、当地日期与时区、修订和重要变化；再显示本人准备、安排与联系入口。收工是预计时必须注明。页底确认按钮不遮挡正文或软键盘，网络异常保留未完成动作并明确没有上报。

看全部当天安排需要相应权限，个人页不能通过展开查看其他人联系方式。链接撤销或到期显示可理解的结果和联系项目负责人入口，不打印内部异常；不提供绕过权限的永久静态公开副本。

纸张与在线阅读内容可不同，但都记录同一发布修订与字段投影；不能为手机另外复制编辑一份通告。

## 6. 导出种类和字段

| 导出项 | 建议格式 | 默认内容、自定义与数据来源 |
| --- | --- | --- |
| 拍摄通告 | PDF、授权 HTML、可编辑 Word | 固定通告修订和对应投影；Word 修改不会回写正式通告 |
| 日计划／人员日程 | PDF、XLSX、授权 HTML | 当前或指定方案，包含准备、拍摄、休息和转场；方案身份固定 |
| 演员工作日表 | PDF、XLSX | 实际有权出演与排期区间；工作、候场、旅行等按明确类型和图例 |
| 时间段器材／道具需求 | PDF、XLSX、CSV | 数量、时段、型号、来源、未知项、共用组；没有库存栏目 |
| 分镜表 | 横／竖 PDF、Word、XLSX | 九基础列或保存的授权字段模板，预设与自定义列可选 |
| 图片横版分镜 | PDF、Word | 图框、镜号、标题、时码、描述与所选字段，图片不拉伸 |
| 九宫格／视觉墙／单镜详细 | PDF、Word | 所选固定镜头及有效构图，单镜长字段可续页 |
| 好莱坞式剧本 | PDF、Word | 场景标题、动作、角色、对白与明确映射的段落；Letter 和等宽剧本字体建议，映射缺失先预览 |
| 好莱坞式制作分镜 | PDF、Word | 剧本信息加图框、拍摄与所选制作字段；不声称认证格式 |
| 工程 PDF | PDF＋恢复清单 | 阅读内容、选定字段、固定素材版本、有效构图、工程码和文件指纹 |
| 剪辑与字幕交换 | EDL、FCPXML、OTIO、SRT、VTT | 固定镜头顺序／时码／旁白；不支持的字段在能力预览列明 |
| 便携项目工程 | JSON 清单＋媒体包／ZIP | 清楚的格式版本、相对路径、固定引用与校验；可读入口说明，不包含密码或环境配置 |
| 后期工作单／交接清单 | PDF、XLSX、Word | 任务、主责、固定输入输出、缺项、版本和依赖 |
| 审阅及返工单 | PDF、Word、XLSX | 固定审阅目标、允许批注、决定、返工任务与负责人；与创作版本分开 |
| 正式交付清单 | PDF、XLSX＋产物包 | 固定交付项／变体、产物、接收范围与验收修订；渲染不自动提交交付 |

本表是目标范围，当前 API 或库只实现部分格式时必须登记缺口。不得将“下载了一个 JSON”作为上述全部工程、PDF、Word 和交换格式已通过。

### 6.1 字段选择

导出页按身份稳定的字段选择，而不是根据当前中文列名判断。选项分基础、预设、自定义三组，可搜索、拖动排序、查看示例和缺值；已删除或无权限字段不提供可选正文。可以保存自己的或有权共享的模板，模板不是新一份业务数据。

默认导出采用所选模板；“与当前共享视图一致”是显式选项，生成时固定列顺序、过滤／排序和修订。表格界面的自定义行高、列宽不强制映射到纸张毫米宽度；导出模板有独立排版宽度，自动换页。字段数据相同，阅读布局不同。

生成预览列出本次镜头／条目数、字段、范围、纸张、图框、素材缺项、权限省略和可见水印；不能静默跳过部分对象。模板引用的列永久删除后失效，要求重新选列，不复活旧历史正文。

## 7. 图框、照片与剧本排版

项目画幅默认传到分镜图框，横竖都可在建项目或后续设置中明确修改。照片保持原比例，使用当前有效构图和黑填充，禁止为占满纸张拉伸。图框尺寸由模板决定，不改原图和已固定构图。

制作横版与竖版分镜时，预览显示图框占据的实际纸张范围；九宫格中的竖图仍竖直，内容不足时分页而非挤压。图注尽量与图片同页，长图注续页标明镜号；大图不自动盖住页码和其他列。

剧本导入和导出先显示场景标题、角色、对白和动作映射。缺失场景信息时显示待确认，不用镜头名称强行构成剧本场景。对白和角色名尽量连排，长对白按模板续页；中文字体有实际嵌入与字形检查。输出文字不加认证、教学用途或责任声明等免责声明。

## 8. 水印与工程二维码／DM 码

每种导出分别设计可见水印与不可见追踪标识。可见水印可以增删改、位置调整，遵循实际字段授权；不可见水印按用户要求保留可追溯隐写能力。只有元数据、文件名或页脚标识不能宣称实现隐写，也不能把二维码当作不可见水印。

抗裁剪与抗截图需要实际验证。计划用合成原图和文档，覆盖完整解码、中心及边角裁剪、多比例重框选、不同像素密度截图、JPEG 压缩、灰度打印／扫描，再统计可恢复比例、误识别和无水印对照。未通过的变换明确列出能力边界，不在正文印免责声明，也不假称所有截图可追踪。

### 8.1 工程码数据提案

用户允许工程码具体数据由实现者决定。本规划推荐默认 QR 分片序列，打印区域受限时可选成熟 Data Matrix 编码器；不是把普通 QR 图重复叠放。码应保持清楚的顺序、静区和纠错参数；选库、分片容量与扫描距离经过实际样例确定，不先承诺固定容量。

每片最少包含：格式标识及版本、导出身份、快照身份、分片序号／总数、内容压缩方式、片段校验、整包指纹，以及这片的压缩载荷。项目内部身份如用于恢复必须明确进入授权恢复清单；码中不放密码、访问令牌、签名私钥、内部地址或他人个人信息。

小型工程可把完整压缩恢复清单分片内嵌；大量媒体使用相对路径、校验和可获得的附件清单，二维码不能容纳全部原图时在预览中明确缺媒体。无附件不宣称完整恢复。可选的在线恢复指针必须再次授权，不能以二维码携带永久访问凭证。

签名只证明清单来源与完整性，不赋予访问权限。扫码导入先限长度、解压规模、版本与校验，再预览对象和字段映射；重复片去重、乱序片重排，缺片、篡改、混入其他工程或不支持版本都不半成品入库。

工程码扫描与文档隐写是两条独立验收：真正把码打印／栅格化后用读取器恢复清单；另对图片／PDF／Word 追踪水印做裁剪和截图实验。源码出现“watermark”或“QR”不算通过。

## 9. 生成作业与权限

渲染作业固定请求身份、项目、请求人、范围、字段投影、业务来源修订、构图、模板版本、水印策略和渲染器版本。同一请求重试返回同一作业；用户更改字段后是新请求，不错误复用旧缓存。

缓存键必须包含授权投影和固定来源，不能用文件标题作为唯一键。生成前、任务执行时、访问和下载时都校验授权及删除标记；分享撤销不能继续从旧缓存下载。签名下载链接有期限，不能代替业务授权。

状态为排队、生成中、已完成、失败、取消、过期。只有真实完成才下载；未知进度显示处理状态，不假造百分比。图片缺失或渲染错误保留清楚的失败项，可恢复作业重试不重复正式业务发布。

生成预览临时留存默认 24 小时，可重建下载默认 7 天，项目可以缩短；正式来源、交付产物和发布正文不套临时期限。临时工件过期时用相同有权固定来源重新生成，不能访问已经永久删除的正文。

Word、XLSX 等下载后可编辑的文件标明原修订身份与生成时间。外部编辑不自动成为 FrameForge 新版本；重新导入必须预览、映射并走权限、修订和事务检查。

## 10. 数据与服务拆分

| 责任 | 边界 |
| --- | --- |
| 排期服务 | 唯一当前方案、条目、时区及锁定；通告不直改排期表 |
| 通告发布服务 | 固定修订、允许投影、接收范围和生命周期；独立事实 |
| 通知服务 | 渠道尝试与回执；不修改发布正文、不代写确认 |
| 文档渲染服务 | PDF／Word／XLSX 和模板排版，只读取固定授权事实 |
| 工程编码服务 | 清单压缩、分片、二维码或 DM 码与扫描恢复 |
| 水印服务 | 可见呈现及独立隐写追踪，记录实际可验证能力 |
| 业务交付服务 | 固定交付产物、验收与退回；下载渲染不是交付状态 |
| 前端 | 使用统一查询和命令展示反馈，不在多个请求之间拼假原子发布 |

调用现有服务和成熟字体、文档、编码库；复用已有 PDF／Word 渲染、工程导出草稿前先检查真实消费者、权限、锁文件和测试，不整份重写。新增业务责任不要全部塞进现有 `document_export.py`；共享 DTO 和路由登记由协调者串行合入。

## 11. 分包路线与验收样例

| 工作包 | 最小可验结果 | 需要的证据 |
| --- | --- | --- |
| X1 固定导出请求 | 范围、字段、授权和修订固化，可重试 | 同修订重试、并发来源变更、撤销授权和永久删除 |
| X2 通告草稿 | 当前方案生成并显示缺项／来源 | 不同个人集合、跨午夜、地点缺项、人工补充冲突 |
| X3 发布与个人页 | 固定修订、投影、旧确认及撤回 | 旧版查看、重要改期、重新确认、无权联系人隔离 |
| X4 分发反馈 | 已配置渠道的真实结果，失败可定向重试 | 接受与送达分开、重复点击、部分失败；未配置不能假成功 |
| X5 纸张与 Word | 上述方向和模板的实际文件 | 续页表头、长中文、长对白、竖图、字体缺字、灰度打印 |
| X6 工程 PDF 与恢复包 | 成熟编码库＋完整清单／媒体缺项预览 | 真实像素扫码、缺片、乱序、篡改、未知版本、解压限额 |
| X7 隐写追踪 | 对实际成品恢复追踪标识 | 裁剪／截图／压缩实验、无水印对照和误识别率 |
| X8 制作工作单和交换格式 | 共用请求和渲染责任，不复制业务数据 | 排期／任务／字幕范围、时码、格式回读与退回回流 |

本轮没有运行这些功能测试。后续优先使用 GitHub 已有合成和脱敏样例；真实用户 Excel、联系人和照片保留本地，不为测试上传原附件。

端到端样例：两场景三镜头、一演员两岗位、不同集合时间、一个跨午夜安排、一次转场、一个共用器材需求、一个未排期需求；生成并发布修订 1；现场超时后草稿变化，旧版保持；发布修订 2，旧确认仍指向修订 1；按人下载和权限撤销；固定素材交接后完成后期产物，审阅退回产生返工；生成可恢复工程包和真实隐写样本。
