## 2026-10-02 第三批

- 需求 5–6：镜头右键菜单按参考图恢复选中、单条旁白计时、前后插入、复制、剪切、粘贴、可恢复删除。移除菜单中的编辑制作方式；列属性菜单保留。动作使用现有权限、完整顺序及 revision 检查、审计与单个事务，复制保留分镜图片、制作步骤、自定义值；内部 ID 不变的剪切移动与新 ID 的复制分开处理。真实系统剪贴板保存项目及镜头版本引用，来源变化则 409，不能静默覆盖。
- 需求 12：真实 XLSX/DOCX/PDF 导入导出；JPG/PNG 导入及本地 CPU OCR，不提供图片导出。保留 CSV、EDL、OTIO、SRT。复用仓库纯 Excel/PDF 解析及旁白计时，不加载旧服务器或旧数据库。
- OCR 选择：核实候选 PaddleOCR 90491 Stars、Tesseract 76787、RapidOCR 8022（2026-10-02 查询快照，非永久排名）。PaddleOCR 在这三个候选中最多；采用 RapidOCR 1.4.4 内置 PP-OCRv4 ONNX 移动模型，CPU 离线运行，无收费接口，无运行时模型下载。参见 [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)、[RapidOCR](https://github.com/RapidAI/RapidOCR)、[Tesseract](https://github.com/tesseract-ocr/tesseract)。
- 解析结果先进入现有预览与映射。扫描页面/图片按单镜头保留完整原图及 OCR 文字，提示人工核对镜头边界和映射；不宣称扫描表格能自动无误还原结构。未识别到文字仍可导入原图。
- Excel 首个工作表、Word 单张表或同结构镜头字段表；PDF 单次 30 页；文件 40 MB，10000 行/200 列，单张图片 10 MB/2000 万像素。生产级持续 OCR 并发应移入已有任务队列；当前每 API 进程共用 CPU 引擎、两个推理线程、识别串行执行。
- 导入原图字节保留，新增图片与镜头在外层事务统一提交；失败清理本事务新文件，原有文件不删。未知列复用现有自定义字段，源表头/原始单元格进入审计快照；不新增数据库结构，不替第 11 条决定待确认的字段语义。
- 修复共用 Excel 解析器的绝对 OOXML 图片关联路径。Excel 字符串不作为公式执行；PDF 复用项目字体并修正 Sarasa 子集同名导致的 Unicode 文字丢失。容器配置增加纯解析文件、现有字体和 OpenCV CPU 系统库；尚未运行容器构建。
